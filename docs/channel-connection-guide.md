# macs 连接接入与 SOP 资料指南

本指南对应 Web **设置 → 连接应用** 中的接入说明。也可从每个渠道的“接入指南”查看具体步骤。内容按当前 macs 源码整理，官方参考资料核对于 2026-10-12；平台菜单、资格和审核规则以当前账号看到的官方页面为准。

## 先认识连接和 SOP

连接是一个消息入口：你在飞书、QQ、钉钉、企业微信、个人微信或邮箱发需求，macs 处理后在那里回复。连接不等于导入单位知识，也不等于给模型开通这些平台的全部权限。

SOP 是 **Standard Operating Procedure（标准操作流程）**，就是一份可以照着办理、可以核对结果的分步说明。它让不同的人有相同的办事依据，减少遗漏，也让出错后容易找到是哪一步的问题。

这里有两种 SOP：

| 类型 | 解决什么问题 | 示例 |
| --- | --- | --- |
| 接入 SOP | 软件怎么连接、凭据去哪里领、怎样确认连通 | 创建钉钉机器人 → 领取凭据 → 配置 Stream → 保存 → 发问候验证 |
| 业务 SOP | AI 应该怎样办理一项工作 | 收集订单 → 核对退换货制度 → 补问缺失材料 → 草拟答复 → 特殊情况请人审核 |

本指南的各渠道步骤就是接入 SOP。业务 SOP 应来自你们实际的制度和岗位做法，不能由聊天渠道自动提供。

## 接入前确认三件事

1. **先能正常使用 Agent。** 在 macs 中用默认 Agent 完成一次普通对话，确认模型可用。渠道收到的消息会交给默认 Agent；渠道字段填好不能代替 Agent 或模型配置。
2. **有平台权限。** 企业自建应用、机器人创建、消息权限或发布可能要管理员批准。QQ 的测试成员、使用范围与上线审核，微信的功能开放范围，也必须先满足。
3. **macs 保持运行、联网。** 当前飞书、QQ、钉钉、企业微信通过长连接接收消息，微信通过长轮询，邮箱通过 IMAP 轮询。电脑关机或 macs 停止后不会继续处理消息。

先配置一个常用渠道即可。页面“已配置”表示字段状态，**不证明平台已经鉴权成功或消息已经联通**。密钥和邮箱授权码只填在配置中，不要放进对话、SOP 材料或截图。

## 飞书：应用机器人与长连接

适合在飞书单聊或群聊中使用 macs。需要能够创建企业自建应用的账号；企业限制创建、授权或发布时，请管理员协助。当前 macs 采用飞书 SDK 长连接，无需另外准备公网回调服务器。飞书官方说明长连接可在能联网的设备上接收事件。[飞书官方长连接发布说明](https://open.feishu.cn/changelog?abilityType=Tool&lang=zh-CN)

| macs 页面字段 | 配置名 | 凭据来源 |
| --- | --- | --- |
| App ID | `app_id` | 飞书开发者后台 → 对应应用 → 凭证与基础信息 |
| App Secret | `app_secret` | 同一页面中的应用密钥 |

1. 打开[飞书开发者后台](https://open.feishu.cn/app)，创建企业自建应用，启用机器人能力。
2. 复制同一应用的 App ID、App Secret；在 macs 的连接应用中添加飞书，填入这两个字段。
3. 在应用权限管理中开通接收用户单聊消息、接收群聊中 @ 机器人消息、以应用身份发送消息等实际需要的权限。图片或文件另按需求申请资源权限，不必为普通问答开通全部企业数据权限。
4. 在事件与回调中选择长连接方式，订阅“接收消息”事件。保存并启用 macs 渠道，保持程序运行。平台要求先建立连接再保存订阅时，按页面提示完成。[接收消息事件与权限](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[配置事件订阅方式](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)
5. 设置应用可用范围，创建并发布版本；需要审批时等管理员批准。更改权限后按平台要求重新发布。
6. 在可用范围内找到机器人，发问候；群聊则先把应用机器人加入群，再 @ 它。

**成功的样子：** 同一会话收到 macs 的实际回复。找不到机器人先查发布与可用范围；收不到消息查订阅与消息权限；收到消息但回复失败查发送权限、默认 Agent / 模型以及 **工作台 → 日志**。

不要把群里的“自定义机器人”Webhook 地址当成 App Secret。自定义群机器人和接收消息的应用机器人是不同类型。[飞书官方自定义机器人说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)

## QQ：机器人 AppID 与 AppSecret

需要 QQ 开放平台开发者账号和已经创建的机器人。能在哪些单聊、群聊或频道使用，由机器人的获批能力、测试成员及上线状态决定。当前 macs 使用 WebSocket 收消息。

先确认你的机器人仍支持 WebSocket。官方事件订阅文档列出 Webhook / WebSocket 两种方式，但官方 SDK 曾提示 WebSocket 逐步下线；不能据此保证任意新机器人仍可使用。如果平台后台只提供 Webhook，当前 macs 的 QQ 适配不能直接套用，需要技术人员确认或补充适配，不能把回调网址填进 App Secret。[QQ 官方事件订阅说明](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)、[QQ 官方 SDK 接入限制](https://github.com/tencent-connect/botgo)

| macs 页面字段 | 配置名 | 凭据来源 |
| --- | --- | --- |
| App ID | `app_id` | QQ 开放平台 → 机器人管理 → 对应机器人的开发或凭据页面 |
| App Secret | `app_secret` | 同一机器人的 AppSecret |

1. 从[QQ 开放平台](https://q.qq.com/)按平台要求注册开发者并创建机器人。
2. 获取同一机器人的 AppID、AppSecret。macs 用 AppSecret 换取并刷新 Access Token；不用自己复制临时 Access Token，也不使用旧 Token 或个人 QQ 密码。[QQ 官方启动接入](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/getting-started.html)、[QQ 官方访问凭证](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/access-token.html)
3. 配置允许的消息场景、测试成员和测试群 / 频道；向外公开使用前按要求审核、上线。
4. 在 macs 连接应用中添加 QQ，填入两个字段，启用并保存。
5. 使用有权限的账号单聊机器人，或在它已经加入的测试群 / 频道 @ 它发问候。

**成功的样子：** 获批场景里的测试消息得到回复。鉴权失败先核对凭据；部分用户不可用先核对测试成员与上线范围；收到消息而没有答案再查默认 Agent / 模型、发送权限与日志。

## 钉钉：企业内部机器人与 Stream

需要有权限创建企业内部应用的钉钉开发者账号。当前 macs 使用 Stream 主动建立连接，接入企业内部应用的机器人，不使用自定义群机器人的 Webhook 地址。官方接入步骤是创建企业内部应用、添加机器人能力、选择 Stream 并发布。[钉钉官方 Stream SDK 接入说明](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs/blob/main/README.md)

| macs 页面字段 | 配置名 | 凭据来源 |
| --- | --- | --- |
| Client ID | `client_id` | 企业内部应用的凭证 / 基础信息，也称 AppKey |
| Client Secret | `client_secret` | 同一应用的 ClientSecret，也称 AppSecret |
| Robot Code | `robot_code` | 应用的机器人配置中取得的机器人编码 |

1. 登录[钉钉开发者后台](https://open.dingtalk.com/)，创建企业内部应用。
2. 添加机器人能力，设置名字和图标，消息接收方式选择 **Stream 模式**。
3. 复制上述三个字段。申请实际需要的消息权限，发布应用并设置可用范围；有权限限制时找管理员确认。
4. 在 macs 添加钉钉渠道，填写三个值，启用并保存。
5. 把机器人加入允许的测试群，@ 它发问候；也可测试平台实际开放的单聊场景。

**成功的样子：** 机器人收到消息并回复。Robot Code 不是显示名称。当前 macs 启动校验要求这项，不要漏填或随便写 `nouse`。收不到消息检查机器人类型、Stream 和可用范围；连接失败查凭据、网络及日志。

## 企业微信：API 模式智能机器人与长连接

需要创建智能机器人的权限；看不到相应入口时先请企业管理员检查功能是否开放及账号权限。当前 macs 对接 WebSocket 长连接智能机器人，字段为 Bot ID、Secret。它不使用旧企业应用的 CorpID / AgentID，也不使用 URL 回调的 Token / EncodingAESKey。

| macs 页面字段 | 配置名 | 凭据来源 |
| --- | --- | --- |
| Bot ID | `bot_id` | 管理后台 → 安全与管理 → 管理工具 → 智能机器人 → API 配置 |
| Secret | `secret` | 同一智能机器人的长连接密钥 |

1. 由有权限的人进入企业微信管理后台的智能机器人管理。
2. 创建或编辑机器人，选择 **API 模式创建 → 使用长连接**。
3. 复制 Bot ID、Secret，保存机器人并设定使用范围。重置 Secret 后要同步更新 macs。[腾讯官方企业微信侧配置步骤](https://cloud.tencent.com/document/product/1759/121473)
4. 在 macs 连接应用中添加企业微信，填写 Bot ID、Secret，启用并保存。
5. 让使用范围内的成员在机器人的会话中发问候，检查实际回复。

**成功的样子：** 企业微信会话收到 macs 回复。认证失败查长连接方式、同一机器人的凭据和 Secret 重置情况；部分成员不能用查范围；处理失败查默认 Agent / 模型和日志。[企业微信官方长连接 SDK](https://github.com/WecomTeam/aibot-node-sdk)

腾讯官方文章还包含其自家智能体平台的发布步骤；macs 只借用其中企业微信侧的建机器人与领取凭据流程。不要把其他产品要求的额外字段搬进 macs 当前表单。

## 个人微信 iLink：扫码取得凭据

使用有资格使用 iLink / OpenClaw 连接功能的微信账号，手机能扫码确认。平台开放范围以微信账号实际情况为准。腾讯官方插件说明扫码保存凭据、通过微信后端长轮询收发消息。[腾讯官方微信连接说明](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md)

| macs 页面字段 | 配置名 | 怎样取得或填写 |
| --- | --- | --- |
| Account ID | `account_id` | 扫码确认后自动填写 |
| Token | `token` | 扫码后自动取得并保存，不必手抄 |
| Base URL | `base_url` | 一般保持默认的 iLink 服务地址 |
| Bot Agent | `bot_agent` | 一般保持默认；只是客户端标识，不是模型或 AI 员工 |
| 允许用户 | `allowed_users` | 可选的微信用户 ID 列表，逗号分隔，不是昵称或手机号 |

1. 在 macs 连接应用中添加 **个人微信 iLink**，填写容易识别的渠道名称。
2. 点击 **扫码连接**，用有权限的微信账号扫码并在手机确认。
3. 等页面确认账号信息已填好；二维码过期则重新获取。
4. 按需要设置允许用户，启用并保存配置。当前允许用户留空，会接受任何能够向该机器人发消息的用户。
5. 保持 macs 运行，在授权后的机器人会话里发问候，确认回复。

**成功的样子：** 扫码确认、凭据已填、真实会话能回复都完成。没有对应功能先核对账号资格；过期二维码重新获取；特定用户没有回复检查允许列表、登录状态和默认 Agent / 模型。

本应用已经实现兼容扫码接入，无需为了使用 macs 再安装一套 OpenClaw 服务或 PC Hook。腾讯插件的安装命令用于它自己的 OpenClaw 宿主。[腾讯官方 iLink 协议资料](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)

## 邮箱：先选择工具还是自动回复渠道

| 入口 | 配置归属 | 用途 |
| --- | --- | --- |
| 设置中的 **电子邮箱** | `email_config` | 给 Agent 的收发邮件工具提供账号；需要在任务中请求相应操作 |
| 连接应用中添加 **邮箱** | `channels[].type=email` 及 `config` | 轮询新邮件，把内容交给默认 Agent，再自动回复 |

这两份配置不是同一个开关。只填写“电子邮箱”不会自动开启邮件机器人。

准备自己能管理的邮箱；开启服务商支持的 SMTP 发信、IMAP 收信，取得客户端授权码或应用密码。企业邮箱可能要求管理员开放第三方客户端。SMTP 是发信通道，IMAP 是收信通道；macs 不需要只为收信再开启 POP3。

| macs 页面字段 | 配置名 | 填写依据 |
| --- | --- | --- |
| SMTP 服务器 / 端口 | `smtp_host` / `smtp_port` | 邮箱服务商的官方客户端设置；当前渠道支持 465 的 TLS 发信 |
| IMAP 服务器 / 端口 | `imap_host` / `imap_port` | 服务商官方设置；当前渠道 993 使用 TLS 收信 |
| 邮箱地址 | `username` | 完整邮箱地址，通常包含域名 |
| 授权码 / 密码 | `password` | 服务商生成的客户端凭据；网页登录密码不一定能用 |
| 发件地址 | `from_address` | 通常同邮箱地址；邮箱渠道启动要求填写 |
| 发件人名称 | `from_name` | 可选，收件人看到的称呼 |
| 使用 TLS | `use_tls` | 按服务商安全要求配置；具体安全连接也与端口有关，不要为排错关闭加密 |

1. 在邮箱官网的账号、安全或客户端设置中开通 IMAP / SMTP，并生成授权码或应用密码。
2. 从服务商官方帮助搜索 **SMTP、IMAP、授权码**，抄录地址、安全端口和登录要求。不同邮箱使用不同服务器，不要照搬。QQ 邮箱的帮助中心可搜索“POP/IMAP 和 Exchange 服务的设置方法”。[QQ 邮箱官方帮助](https://service.mail.qq.com/)
3. 需要 Agent 按指令操作邮件时，填写独立电子邮箱配置，启用并保存；在 Agent 对话里明确说明收信或发信需求。
4. 需要自动回复新邮件时，另外添加邮箱渠道，填全收信、发信、授权码和发件地址，启用并保存。初次验证用专门测试邮箱，避免重复启用同一邮箱的监听渠道。
5. 从另一个地址向监听邮箱发一封新邮件，主题“连接测试”，正文“你好，请回复连接成功”。默认轮询约 30 秒，还要等待模型处理。

**成功的样子：** 新邮件被收到、Agent 处理成功、回复邮件发出。登录失败查 IMAP 开启和授权码；能收不能发查 SMTP、发件地址与服务商限制；完全不自动回复查是否添加了邮箱渠道、邮件是否在监听收件箱里、模型是否可用。

邮箱授权码由服务商发放，macs 不能替用户领取。不同邮箱的具体开通入口和访问条件以官方帮助为准。

## 自定义：需要对应适配器

填写自定义类型和 JSON 不是自动开发新渠道。当前后端必须已经实现并注册这种类型；未知类型会被忽略。需要技术协助时，索取三份材料：**平台官方文档、macs 适配器参数、真实消息验证步骤**。

先确认支持类型，再按该适配器办理应用权限和凭据，填写 `type`、`config`，启用并保存。看日志确认渠道加载，再按其专用 SOP 做收发验证。不能通过复制其他平台的 API Key、字段名或 Webhook 地址，变出一种未实现的渠道。

## 业务 SOP 资料具体怎么拿

优先找本单位现有资料：主管或流程负责人确认的制度、岗位操作手册、培训资料、模板和成功案例。资料由谁负责、目前是否有效，也请一并确认。没有手册时，就先整理下面六项给负责人核对；不要把陌生公司的流程直接当成本单位制度。

1. **适用场景：** 处理哪些请求，哪些不适用。
2. **所需材料：** 开始前需要哪些信息、文件和权限。
3. **一步步操作：** 按什么顺序、每步做什么、由谁做。
4. **每步检查：** 什么证据说明这一步做对了。
5. **结果示例：** 最终交付内容、字段或答复格式。
6. **人工确认：** 哪些情况必须审核、批准或升级给负责人。

例如客服退换货流程：收集订单和原因 → 核对本单位退换货制度 → 缺资料先补问 → 草拟答复 → 特殊情况和退款交负责人确认。退换期限、费用标准、审批权限都要来自自己的制度，不能让 AI 猜。整理复用案例时去掉个人信息和一次性订单数据。

资料整理后按用途放进 macs：

| 入口 | 适合放什么 | 怎样发挥作用 |
| --- | --- | --- |
| 知识库 | 制度、说明、参考资料 | 给检索提供依据；上传不等于硬性执行步骤 |
| 我的 Skill | 可复用的知识、方法和操作说明 | 在任务中选择或明确调用对应 Skill |
| AI 员工 | 岗位职责、范围、质量和边界 | 配合相关知识或 Skill 处理岗位工作 |
| 工作流 | 必须按预设步骤办理、检查或审批的工作 | 用配置步骤与审批控制执行顺序；普通文字手册不能代替工作流 |

用一份已确认成功案例和一份缺材料案例验证：看 AI 是否补问、输出是否符合要求、需要人工确认时是否正确等待。让流程负责人核对后，再重复使用。

## 统一验证和失败定位

阅读说明、切换指南不会修改配置或调用模型。**实际在渠道发问候会调用所用模型；平台模型可能扣费。** 当前页面没有通用“测试渠道”按钮，验证应在对应聊天软件或邮箱真实发一条简单消息。

排错按顺序：

1. 平台的应用、机器人和使用资格是否正确？
2. 凭据是否对应同一个应用、是否重置过、字段是否填全？
3. 是否启用并保存，macs 是否仍运行且能联网？
4. 事件、消息权限、发布、测试成员与使用范围是否正确？
5. 默认 Agent 是否存在、模型是否可用，发送回复的权限是否足够？
6. 在 **工作台 → 日志** 找平台或模型返回的具体错误，交给管理员 / 技术人员时移除密钥和个人资料。

## 给维护者的事实入口

界面字段以 `web/app.js` 的 `CHANNEL_SCHEMAS`、渠道编辑器与 `renderChannelsList` 为准，阅读指南为 `web/channel_guides.js` / `.css`。渠道启动校验在 `internal/app/gateway.go` 的 `loadChannelsFromConfig`，热更新装配在 `internal/app/mac.go`，协议实现位于 `internal/channels/`，默认 Agent 调用在 `internal/channelhost/`。

- 飞书：`feishu.go`，应用凭据、SDK 长连接与接收消息事件。
- QQ：`qq.go`，`QQBotCredentials.AppSecret`、Access Token 刷新和 WebSocket。
- 钉钉：`dingtalk.go`，Stream；Gateway 启动校验要求 `robot_code`。
- 企业微信：`wecom.go`，WebSocket 和 `bot_id` / `secret` 订阅鉴权。
- 微信：`weixin.go`，扫码取得 `account_id` / `token`、长轮询和用户白名单。
- 邮箱：`email.go`、`email_host.go`，IMAP 轮询与 SMTP 回复；独立邮件工具配置不等于邮箱渠道。

官方动态站点若无法直接读取正文，按已验证的厂商文档入口和官方 SDK 说明核对，不能据此假定任何账户都已获权限、已发布或已连通。
