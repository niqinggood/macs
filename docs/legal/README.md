# macs 版权材料与发布说明

新版本软件名称为 **macs**，全小写。多智能体协作系统是功能说明；申报表、说明书及源程序页眉中的软件名称统一填写 macs。历史 openkitty 名称用于核对旧登记关系；兼容入口、配置、环境变量及现有正式许可证名称保留原文。

## 权属信息

复制 [登记字段模板](registration-fields.template.json) 到被忽略的 `.local/` 目录后填写。法定权利人、实际开发完成日期、首次发表情况、开发与权利取得方式、旧证书信息及合同附件由申请人据实确认。材料编制日期、品牌署名和 Git 提交时间均不能代替这些事实。

旧 openkitty 如已登记，核对原名称、版本、登记号及权利人与本次申请人的关系。持续升级的重要改进可以整理为修改说明；仅更名时，应按实际情况核对登记事项的变更或补充。涉及其他权利人时保存相应许可、转让或合作开发证明。

## 保存申报版本

在仓库根目录运行以下命令，归档当前有效源码，包括尚未提交但未被忽略的文件：

```powershell
python scripts/legal/source_archive.py create --output .local/copyright/macs-v1.1.8 --version V1.1.8
python scripts/legal/source_archive.py verify --directory .local/copyright/macs-v1.1.8
python scripts/legal/source_archive.py verify --directory .local/copyright/macs-v1.1.8 --worktree
```

归档目录必须是新的私有目录。归档包含源码 ZIP、逐文件摘要、基线提交和工作区状态标记；不复制 Git 历史、真实配置、运行数据或软著证件。需要保存对应二进制时，使用 `--binary <已构建程序路径>`，文件仅进入私有归档。校验可以分别确认归档完整性和当前工作区差异；摘要不代替完整源码。

源码交存材料应从确定的完整源码范围按固定文件顺序生成，记录前后连续区间、原文件行号和摘要。不要在申报后覆盖归档；后续改进另建版本目录。

## 文档与运行证据

说明书围绕实际入口、输入、操作、返回内容和限制编写。补充问答回答、Agent 工具执行与交付文件、AgentOS 提交及终态查询的真实案例。演示数据使用虚构业务资料，截图不得显示模型密钥、客户数据或会话凭据。模型或外部服务未配置的部分只说明操作与依赖，不编造成功结果。

普通交存通常为程序和一种文档各自前后连续 30 页；不足 60 页提交全文。程序通常每页不少于 50 行，文档通常每页不少于 30 行。封面、图片页及其他特殊页如何处理，应按申报时登记机构要求确认。页眉名称、版本、页码和结束页应逐项核对。

## 第三方材料与发布包

[第三方材料说明](../../THIRD-PARTY-NOTICES.md) 和 `third_party/components.json` 记录组件、来源、许可文件及待核对事项。运行以下命令重新采集当前 Go 依赖、前端资源和内置技能；原始许可和 NOTICE 文本按组件保存在 `third_party/licenses/`：

```powershell
python scripts/legal/third_party_inventory.py
```

许可证发现和文本分类是整理工具，不等于已经完成每个文件的权属审查。未找到授权依据的外来材料需要补证、取得授权或替换；保留署名不能代替分发许可。内置文档技能的替换记录见第三方材料说明。

对外发行时携带 LICENSE、NOTICE、COMMERCIAL-LICENSE.md、TRADEMARKS.md、BRANDING.md、THIRD-PARTY-NOTICES.md 及完整 `third_party/`。源码包和二进制包均应保留适用声明。申请材料、完整私有源码归档、身份证明及签章不进入公开发行包。
