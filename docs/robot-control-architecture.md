# OpenKitty 机器人身体控制架构

OpenKitty 的 Linux/ARM64 二进制是边缘大脑的运行底座。要让自然语言或语音安全地控制无人小车、机械臂和机器人，还需要在 Agent 与硬件驱动之间增加一层确定性的机器人运行时，不能让大模型直接写串口、电机寄存器或任意 ROS2 topic。

> 当前同时提供通用 `plc_modbus`、`uart` 和 `ros2` 底层工具。具体型号 Skill
> 可以通过这些工具实现型号操作语义；OpenKitty 核心不判断前进、后退、左转、
> 右转或停止对应的底层参数。这里描述的 `robot_*` 运行时继续作为 `sim` 兼容
> 闭环。通用工具边界见
> [底层硬件工具](hardware-transport-tools.md)。

## 控制链路

```text
文字 / 语音
    ↓
ASR（语音转文字）
    ↓
意图解析（自然语言 → 结构化动作）
    ↓
安全策略（权限、限速、工作区、碰撞、急停、超时）
    ↓
Robot Runtime（动作状态机、看门狗、反馈）
    ↓
ROS2 / CAN / UART / Modbus / 厂商 SDK
    ↓
底盘、机械臂、夹爪、传感器
```

实时闭环必须留在 MCU、PLC、ROS2 控制器或厂商驱动中。OpenKitty 负责理解目标、调用受约束动作、观察结果和编排多步任务。

## 第一组工具

| 工具 | 作用 | 默认权限 |
|---|---|---|
| `robot_status` | 读取连接、模式、电量、里程计、关节和急停状态 | 只读 |
| `robot_stop` | 立即停止底盘和机械臂，并取消当前动作 | 始终允许、最高优先级 |
| `robot_move` | 按距离或短时速度控制底盘前进、后退和转向 | 写入、受限 |
| `robot_command` | 严格解析“前进20厘米、右转90度、停”等短文本或 ASR 结果，并复用同一安全运行时 | 写入、受限 |
| `robot_navigate` | 移动到预定义航点，不接受任意未授权坐标 | 写入、受限 |
| `robot_arm_pose` | 移动到预定义姿态，或在关节软限位内运动 | 写入、受限 |
| `robot_gripper` | 打开、关闭夹爪并限制力矩 | 写入、受限 |
| `robot_sensors` | 获取避障、IMU、里程计、力矩和限位信息 | 只读 |

工具参数必须是 JSON Schema 中的物理量，例如 `distance_m`、`linear_mps`、`angular_rps`、`timeout_ms`，不能把任意 shell 命令或寄存器地址交给模型。

## 当前已实现的闭环

当前版本已经实现第一阶段的 `sim` 驱动以及 `robot_status`、`robot_stop`、
`robot_move`、`robot_command`。运行时提供：

- 全局和设备两层 `allow_motion` 开关，默认都关闭；
- 米、米/秒、度、弧度/秒和毫秒物理量校验；
- 单次距离、转角、速度、动作时长和看门狗硬限制；
- `command_id` 幂等检查，同一个 ID 不允许改变动作参数；
- 非阻塞动作回执与可抢占的软件停止；
- `.openkitty/robot/audit.jsonl` 追加式动作审计；
- 审计无法落盘时拒绝运动，但停止命令仍优先到达驱动；
- 严格的中英文短指令解析；缺少单位、多步骤和模糊指令直接拒绝。

`sim` 只更新估算位姿，不访问 GPIO、串口、CAN、ROS2 或 Modbus，因此不能声称
实体机器人已经运动。接入真实硬件时必须新增 `RobotDriver` 适配器，并保留上层
工具和安全规则不变。

## 本地控制 API

Web 控制台、本地 ASR 或同机程序可以使用同一运行时：

```text
GET  /api/robot/status?device=sim_rover
POST /api/robot/command
POST /api/robot/stop
```

`/api/robot/command` 只接受严格短指令：

```json
{"text":"前进20厘米","command_id":"voice-20260723-001"}
```

`/api/robot/stop` 接受设备、命令 ID 和审计原因：

```json
{"device":"sim_rover","command_id":"stop-20260723-001","reason":"operator stop"}
```

没有配置 Gateway API Key 时，这三个端点只允许回环地址上的无 Origin 或同源
请求；配置 API Key 后必须提供正确的 `X-API-Key`。API 不提供任意 shell、串口
字节、ROS topic 或寄存器写入能力。

## 传输适配层

统一的 `RobotDriver` 接口负责隔离具体设备：

- `sim`：第一阶段默认驱动，用于测试动作、安全规则和 UI；
- `ros2`：适合导航、机械臂轨迹、传感器和复杂机器人；
- `serial_can`：适合树莓派连接 MCU、电机驱动板和小车底盘；
- `modbus`：适合 PLC、工业机械臂外围设备和 IO。OpenKitty 已有带目标白名单与写入开关的 Modbus 工具，可以作为工业设备接入基础；
- `vendor_sdk`：为特定品牌机械臂或底盘封装其官方 SDK。

上层工具不随设备变化，只替换驱动配置。这样同一句“前进半米”可以在模拟器、ROS2 小车和串口小车上执行一致的安全语义。

## 必须在模型之外实现的安全规则

1. 物理急停优先于任何软件命令，`robot_stop` 不排队。
2. 看门狗在控制心跳中断后自动输出零速度并制动。
3. 速度、加速度、关节角、力矩、工作空间和单次动作时长都有硬上限。
4. 避障、限位、倾倒和失联状态直接拒绝运动，不等待 LLM 判断。
5. 每个写动作带 `command_id`，支持幂等、取消、超时和完整审计。
6. 首次运动、危险区域运动和机械臂抓取默认需要确认；只读状态不需要确认。
7. 云端断网不影响本地急停、避障和手动接管。

## 语音控制

短指令应走本地快速路径，例如“停”“前进二十厘米”“左转九十度”。ASR 后先匹配严格动作语法，通常不需要调用大模型；“去仓库找到红色箱子并拿回来”这类多步目标再交给 Agent 规划。所有路径最终都生成同一种结构化动作并经过同一安全层。

## 推荐开发顺序

1. ✅ `sim` 驱动、状态、停止、移动、看门狗、限速、幂等和审计；
2. ✅ 严格文本/ASR 短指令解析；
3. Web 手动控制台与运行状态可视化；
4. 接入第一台真实小车的 ROS2 或串口/CAN 驱动；
5. 接入本地 ASR，完成麦克风到 `robot_command` 的离线语音闭环；
6. 增加导航、摄像头和避障；
7. 再实现机械臂姿态、夹爪与视觉抓取。

在开始第三步前，需要确定第一台设备的型号、控制板、操作系统、通信协议、速度单位、急停接口和传感器清单。
