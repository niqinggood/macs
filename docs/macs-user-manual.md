# macs 使用手册

**正式名称：macs（麦卡斯）｜小名：openkitty**  
**文档更新：2026-09-29｜适用范围：个人本机使用为主，附团队与系统接入说明**

macs 是一个能够使用工具、处理文件、记住工作偏好并执行多步骤任务的 AI 工作系统。你可以用它整理资料、分析数据、修改代码、生成文档，也可以把重复工作交给 AI 员工和工作流。

本手册按照当前源码和 Web 界面整理。功能是否可用还取决于所用构建、模型、工具配置及本机依赖。更新源码后，需要重新构建并运行新的程序，最近的修复和内嵌界面才会生效。

程序和配置继续沿用 `openkitty` 的兼容名称，例如 `openkitty.exe`、`openkitty-config.yaml` 和 `.openkitty/`。看到这些名称时，指的仍是同一个产品。

## 1. 先认识 macs

### 1.1 可以做什么

| 你要完成的工作 | 使用方式 | 结果通常在哪里 |
| --- | --- | --- |
| 阅读资料、归纳重点、比较方案 | 新建任务，上传材料并说明要求 | 对话结果、交付物或文件链接 |
| 整理表格、分析数据 | 提供数据与统计口径，指定输出格式 | 分析说明、表格、图表等产物 |
| 编写和修改代码 | 选择工作目录，说明问题和验收方法 | 工作目录中的代码与验证记录 |
| 填写固定 Word 模板 | 工作台 → 文档自动化 | 可预览、下载的 DOCX 文件 |
| 查询长期资料 | 知识库中导入文档，再进行检索或问答 | 检索片段与回答 |
| 按固定步骤反复办事 | 使用技能、AI 员工或工作流 | 执行记录与交付文件 |
| 操作网页或本机应用 | 用自然语言描述目标，由可用的界面工具执行 | 操作结果、截图或校验回执 |

浏览器、桌面操作、音视频、Office/PDF 转换、外部编程 Agent 等能力可能需要相应软件、运行时或服务连接。内置工具能被发现，不等于所有依赖都已安装。

### 1.2 六个常见名称

| 名称 | 可以怎样理解 |
| --- | --- |
| 模型 | 提供语言理解、推理或视觉能力的服务；可以来自云端，也可以在本机运行 |
| 智能体 / Agent | 使用模型和工具执行任务的助手；具有自己的提示、工具范围和记忆设置 |
| 工具 / Tool | 一次具体动作，例如读取文件、检索资料、执行命令或生成文档 |
| 技能 / Skill | 完成某类工作的操作说明与能力约束；可以在已有 Agent 上启用 |
| AI 员工 | 带业务身份的助手，例如资料整理或客户研究岗位，可绑定知识与工作流 |
| 工作流 / Pipeline | 把多个步骤组织成可跟踪的流程，按配置处理输入、产出、审批和失败 |

刚开始使用时，先配置一个模型和一个智能体，完成单个任务即可。遇到稳定重复的工作后，再增加技能或工作流。

## 2. 第一次启动

### 2.1 选择正确的程序包

| 电脑或服务器 | 对应包名标识 |
| --- | --- |
| 常见 Windows 64 位电脑 | `windows-x64` |
| Intel / AMD Linux 服务器 | `linux-x64` |
| ARM64 Linux 设备 | `linux-arm64` |
| Intel 芯片 Mac | `macos-intel` |
| Apple Silicon Mac | `macos-apple-silicon` |

目前提供的三平台 Go 程序包内嵌 Web 界面，解压即可运行程序，不需要先安装 Node.js 或编译前端。它们与 Electron 桌面安装包是不同的交付形式。

将程序包解压到可写目录。不要在压缩软件内部直接运行，也不要把新版本压到唯一的数据备份上。

### 2.2 Windows 启动

进入解压后的目录，在 PowerShell 中运行：

```powershell
.\openkitty.exe --version
.\openkitty.exe --path . --port 8090
```

第一条查看版本，第二条将当前目录作为工作区并请求使用 8090 端口。也可以直接双击程序，此时使用当前配置和启动位置。

### 2.3 Linux / macOS 启动

在解压后的目录打开终端：

```bash
chmod +x ./openkitty
./openkitty --version
./openkitty --path . --port 8090
```

如果拿到的是单独的二进制，文件名可能带版本或平台后缀；请把命令中的 `openkitty` 换成实际文件名。

### 2.4 打开界面

按上述命令成功启动后，通常访问：

```text
http://localhost:8090/web
```

**实际地址以终端的“启动 Web 服务，监听地址”输出为准。** 当前配置模板使用 8080 端口；既有配置也可能使用其他端口。个人运行方式下，端口被占用时还可能选择其他可用端口。不要仅凭旧文档固定访问 8090。

正常桌面模式会尝试打开浏览器；无界面模式或自动打开失败时，手动输入地址即可。运行期间保留服务进程；关闭网页不等于关闭服务。

`--port` 会尝试把端口写回当前配置。需要换端口时，可停止程序后使用另一端口重新启动，并查看新的监听地址。

### 2.5 首次运行会创建什么

没有找到配置文件时，程序会尝试在用户目录下生成：

```text
~/.openkitty/openkitty-config.yaml
```

Windows 中的 `~` 对应当前用户目录。首次启动的模板只是起点，模板里的模型名称、服务地址和占位密钥不保证适合你的账号或本机环境。进入设置后完成下一节配置。

如果启动进入配置修复流程，先按照日志找到当前配置及备份位置，再在设置中补齐模型。不要把占位字符串当作有效 API Key。

## 3. 配置模型与智能体

### 3.1 打开设置

左下角提供 **登录**、登录后的账号菜单和 **设置**；右上角提供 **帮助**。点击登录在当前页打开模态框，使用轻遮罩保留后面工作区的可见性，支持用户名、邮箱或手机号与密码登录；成功后关闭弹窗并刷新账号、积分及平台模型状态，保留当前对话和输入。账号菜单向上展开，可进入用户中心或退出登录。小屏布局将账号和设置入口放在顶部。登录后，科技社区动态展示在 **科技前沿**。点击帖子会在当前页面弹出阅读窗口，展示标题、作者时间、章节目录、正文图片、表格和代码，支持大字阅读、手机布局与深浅主题。卡片区和弹窗正文隐藏滚动条，仍可用滚轮、触控板和触屏滚动。阅读窗口支持关闭、最小化及最大化；页面底部可进入科技社区继续查看讨论。

点击左侧底部的 **设置**，进入 **系统设置**。

对话输入框下方、**上传图片** 旁边显示两个独立选择：**模型名称 ▾** 和 **Agent**。模型面板直接切换当前模型，每个模型和当前选择都显示 **平台** 或 **自定义** 来源标签，并提供 **添加自定义模型** 与 **管理模型** 入口。Agent 默认选中现有配置里的默认助手，可切换到其他已配置助手，也可点击 **＋自定义 Agent**，填写名称和工作要求后 **保存并应用**。保存成功后自动选中新建的 Agent。

网页对话明确选择模型时，Agent 模式和简单问答都使用输入框所选模型；切换 Agent 只切换助手的身份、工作要求和工具权限。Agent 单独配置的模型继续作为其他渠道、未指定模型的 API 请求等入口的默认值，网页选择不会取消这些配置。新 Agent 默认跟随当前模型。

输入框旁的 **Agent 模式 / 简单问答** 选择对话方式。Agent 模式可以执行工具、Skill、AI 员工和工作流；简单问答直接调用所选模型，保留历史，但不会启动 Agent 或将 `@名称`、`/pipeline` 等文字解释成执行命令。文本模型当前仅接收文字；图片和视频模型可以使用参考图。运行中的请求完成后才能切换方式。

将鼠标移到 **Agent 模式 / 简单问答** 上，可以查看 **规划并执行 / 直接回答** 的说明；选择图片、音乐或视频模型时提示 **直接生成**。说明通过悬停显示，输入区保留主要选择。切换到英文后，模式选项和说明一起切换为英文。

右上角 **Aa** 可以调节整个界面的字号，提供 **标准 100% / 舒适 110% / 大字 120% / 更大 130%**。默认使用舒适档，比原界面放大约 10%；选择立即生效，并保存在当前浏览器，刷新后沿用。字号调整不会改变当前对话、输入或模型选择。

模型选择右侧的 **提示词模板** 打开模板卡片库，按用途分类，也可搜索。模板采用 RTOC：**R 角色、T 任务、O 输出、C 背景与约束**。选择模板后按需补充信息：内置商品、买家、背景和风格使用可清除的通用默认值；事实、材料、收件人、主题和时长默认留空，自定义变量也可以留空。空参数不保留占位符，可以在对话框继续补充。预览完整提示词再填入输入框；已有内容时明确选择 **追加** 或 **替换**。应用后输入区默认显示模板名称，点击名称可展开完整提示词并编辑，再点可收起；追加时保留原有文字可见。折叠仅改变显示，发送的始终是完整提示词和补充内容。应用模板只填写消息，不发送、不收费，也不更改模型、对话方式或已添加的附件。图片类模板请先选择生图模型，并通过图片按钮添加参考图；视频和音乐类模板同样需要相应模型。

图片、音乐生成窗口提供 **最大化窗口 / 还原窗口**，也可使用左上角窗口按钮。描述旁的 **提示词模板** 只显示对应类型的模板，包含产品摄影、风景、插画、Lo-fi、民谣和电影配乐等 RTOC 预设，支持复制成自己的模板。选择后填入生成描述，已有内容时选择追加或替换；不会改动主对话草稿、模型或歌词，也不会自动生成或扣费。

内置模板提供产品图美化、商品文案、海报、视频、音乐和办公写作等用途。点击 **新建模板** 可填写名称、分类、适用模型类型和 RTOC 四部分；可用 `{{名称}}` 设置使用时再填写的变量。适用模型类型是用途提示，不会切换当前模型。自己的模板可编辑或删除，内置模板可复制后修改。自定义模板保存在当前浏览器，刷新后继续使用，最多保存 200 个，不会自动同步到账号或其他设备；清除浏览器站点数据会删除这些模板。保存失败时窗口保留编辑草稿，并提示原因。

模型面板按 **对话 / 生图 / 音乐 / 视频** 分类，显示具体型号、来源及后台价格。**对话** 中的 **平台** 一栏读取账号服务的公开目录；点击型号直接保存并选用，无需再打开设置或填写 API Key。默认账号和模型服务统一使用 `https://www.sicurrent.com`，目录地址为 `/api/macs/v1/catalog?type=all`；自行配置的账号服务地址或环境覆盖继续优先。下一次简单问答或单 Agent / Skill 任务均使用所选对话模型。切换模型本身不调用生成接口、不扣费；实际发送时需登录平台账号。目录暂不可用时，界面说明无法获取具体型号并提供 **刷新**，不会编造可用模型。

使用平台账号扣费的模型时，点击发送会先检查当前登录状态。未登录时在原页面弹出登录框，保留输入、提示词模板和附件，不创建会话、任务或生成请求；登录后再次点击发送。对话、Agent、生图、音乐和视频沿用这一步检查。自定义模型及已配置访问密钥的兼容调用继续使用原授权方式；检查服务暂时不可用时提示稍后重试，不把服务故障当成未登录。

平台模型选项在型号后面同一行显示 **扣费 X 积分**，免费型号显示 **扣费 0 积分（免费）**，不另起一行。悬停费用可查看每次调用或生成的计费单位及 **成功后扣费**。价格从平台目录读取，已有的平台配置也显示同一型号的目录价格；目录未提供可确认价格时显示 **价格待确认**。文本模型按实际模型调用次数计费，Agent 的一条任务可能包含多次调用。

在输入框的模型面板切换到 **生图**、**音乐** 或 **视频**，点击具体型号后，仍使用当前输入框和对话记录，自动切到 **简单问答**。填写内容后点击 **发送**，直接调用平台生成 API。选择型号不会生成内容或扣费，也不会覆盖 Agent 的文本模型配置；切回 Agent 模式或选择对话模型时恢复普通输入框。图片可选比例；视频按平台能力提供时长和清晰度；音乐可选歌曲、纯音乐或配乐，并可填写已有歌词。

图片和支持参考图的视频模型可通过 **上传图片**、粘贴或拖入图片，当前每次支持 **1 张 JPG、PNG、WebP 或 GIF，不超过 10MB**。有参考图时执行改图或图生视频，没有参考图时执行文生图或文生视频。音乐模型不接收图片。结果直接显示在对话消息中：图片可预览，音频和视频可播放，也可打开或下载。图片结果的 **用作参考图 / 继续修改** 会把结果加入输入框，填写修改要求后再发送；暂不能直接引用的结果可下载后重新上传。

生成消息显示进度和费用状态。离开页面后平台任务继续运行，重新打开原对话时读取已保存任务并更新结果，不重新生成。生成记录归属于提交时登录的账号，切换账号后不展示其他账号的记录；重启 macs 后重新登录原账号即可继续查看。侧栏 **更多 → AI 创作 · 图片与音乐** 保留独立窗口及平台最近记录，包含视频记录，可用于核对提交结果。未登录也可查看公开模型和价格，登录后才能读取视频参数或生成；平台凭据保留在 macs 后端。

生图、视频输入框显示平台提供的 **费用** 和计费单位；结果消息显示 **实际扣费 / 已退款 / 免费** 与积分金额，未确认费用显示 **待核对**，不自行推定已扣费。音乐结果采用唱片封面卡片，显示歌曲名称、模型和播放器。

独立创作窗口左侧设置模型与内容，右侧预览作品和最近记录。图片用比例按钮选择构图，音乐用按钮切换歌曲与纯音乐，歌曲可展开 **歌词（可选）** 输入已有歌词。短提示词按钮只填入描述，仍需点击生成才提交；音乐结果可直接试听、展开歌词或下载。图片、音乐各有配色和预览样式，手机上按上下顺序显示，支持明暗主题。

右上角 **导出** 保留上传的参考图、完整生成图片、音乐卡片、歌词及扣费状态。图片会先读取并嵌入导出内容，再生成 PNG 或打印 PDF；读取失败会明确提示，避免缺图。导出预览中音乐可以播放，PDF 保留播放 / 下载链接，PNG 中显示音乐卡片与歌词，音频仍可从原对话播放或下载。播放平台音乐链接需登录原账号。导出只读取已保存的结果，不触发新的生成或扣费。

**帮助说明** 末尾也提供图片和 PDF 导出。使用独立的浅色版式，代码块为浅灰背景，去掉导航和操作按钮，完整展开说明内容。长说明按大小拆成编号 PNG，避免生成过大的画布；PDF 自动分页。导出不改变当前弹窗的主题、滚动位置或展开状态。

**科技前沿** 在登录后的空白对话中展示。发送第一条消息、打开已有对话或等待历史消息加载时自动收起；切回空白对话时恢复。手动点击 **收起** 后保留收起状态，账号信息刷新不会让它盖住已有对话。

目录读取和查看生成记录不调用生成模型、不扣费。模型是否可用、生成价格和结算由平台管理；现有音乐免费策略保持不变。提交结果无法确认时不会自动重试：先点击 **核对平台生成记录**，核对后明确 **开始新一次生成**，避免重复请求和收费。当前图片、音乐和视频生成使用平台模型；自定义文本模型继续用于对话。

当前选择保存在 `default_model`，值为 `model_cfg` 中的配置名称；未设置时沿用既有默认助手的可用模型，再按现有模型优先级选取。显式选择的模型被删除或未配置完整时会报错，不会静默换用其他收费服务。`GET /api/models` 仅返回模型名称、来源、就绪状态、是否使用登录账号、Agent 的模型继承关系和配置版本，不返回密钥或上游地址；本机同源 `PUT /api/models` 携带 `config_revision`，用 `default_model` 选择已有配置，或用 `platform_model` 选择平台目录中的 ID（两者互斥）。后者由后端重新确认型号是可用的文本模型，从账号服务确定地址，创建或复用免密钥配置，再按既有设置保存与热加载流程应用；不覆盖自定义配置、访问密钥或 Agent 的独立模型。下一次任务按新选择创建 Agent，已经创建的任务 Agent 保留自己的模型快照。

输入框的模型名称和来源显示下一次网页任务将使用的模型。发送普通对话、简单问答或 Skill 时，网页只提交 `model_config` 配置名称；后端验证本机同源请求和配置就绪状态，为该任务冻结模型配置。选了 SICurrent 平台模型时，每轮推理调用 SICurrent，并按提交任务时登录的账号扣费；Agent 工具仍由本机 macs 执行。选择自定义模型时调用自己的服务。运行中的任务不会随随后切换的模型改变服务商或扣费账号，配置缺失时明确报错。AgentOS 的岗位快照及其他渠道默认规则保持各自的原有契约。

- **自定义模型**：填写自己的服务地址、模型和 API Key，也支持本地模型。费用由你使用的服务商收取，不扣平台积分。
- **使用平台模型**：先在左下角登录账号，再从输入框旁直接选择具体平台模型，按本人账号余额计费，无需创建或填写 API Key。高级配置仍可从系统设置编辑；服务地址默认读取当前账号平台，模型填 `platform:default` 时使用后台当前默认模型，也可点击 **读取平台模型** 查看可选项和价格。平台服务商密钥保留在后台。读取目录和自动健康检查不触发生成收费；**测试连接** 会实际调用一次模型，可能产生费用。
- **高级接入**：在模型编辑器的 **更多模型选项** 勾选 **使用账号访问密钥**，可继续配置钱包访问密钥，供脚本、无人值守服务或第三方程序使用，按密钥所属账号扣费。自定义模型仍使用自己的供应商 API Key。

登录调用的凭证仅保存在 macs 后端的内存会话中，不写入模型配置或交付物。每个 Web 任务绑定提交时的账号；退出登录或会话到期后不再发起该任务的新模型请求，也不会改用后来登录的账号。已提交的调用仍按实际结果结算。重启后需要重新登录；恢复任务不会自动借用当前登录账号。其他渠道和 AgentOS 服务调用不继承浏览器登录，需显式配置自己的访问密钥。

平台模型接口需要 Nova 后台启用 `/api/macs/v1`，本地代码完成不代表线上接口已发布。收费价格由后台管理员设置，成功调用结算，失败释放预留余额。复杂任务可能多次调用模型，计费次数按实际模型请求计算，不能把一个任务等同于一次收费。平台模型当前兼容完整 JSON 和完整结果后的 SSE 输出；逐 Token 的实时透传尚未启用。

常用设置分为 **AI 服务、我的助手、工作文件、助手能做什么、连接应用**。**助手能做什么** 提供阅读网页、处理办公文档和操作网页与应用三个工具开关，修改后点击 **保存并应用** 生效。端口、并发、调试、PLC 和配置文件说明放在 **高级设置**，日常使用可保留当前值。

首次使用按以下顺序操作：

1. 在 **AI 服务** 中点击 **连接 AI 服务**，选择服务商，填写密钥、模型 ID 和服务地址。
2. 点击 **测试连接**。测试只发送一条简短消息，不保存设置，服务商可能收取少量费用；连接测试限运行 macs 的本机访问。
3. 保持 **设为当前模型** 选中，点击 **保存并应用**。尚无助手时自动创建跟随当前模型的默认助手，已有独立模型选择保持原样。
4. 返回对话，给默认助手发一条简短消息。

编辑弹窗中的 **保存并应用** 会直接提交设置，不需要再保存一次。保存失败时保留修改，可在当前页面修正并重试。工作文件夹或助手工具开关等页面的改动使用顶部同名按钮保存。

在 **我的助手** 中可以选择默认助手、设置工作要求和对话记忆；回答长度等参数收在 **更多回答选项**。**连接应用** 提供飞书、企业微信、钉钉、QQ、微信 iLink 和电子邮箱入口。

### 3.2 云端模型需要填写什么

| 字段 | 填写原则 |
| --- | --- |
| 模型配置名 | macs 内部用于选择的名称，例如 `my-model`；不必等于供应商的模型 ID |
| 类型 | 与服务的接口类型匹配，按设置页面支持的类型选择 |
| API Key | 你自己的有效密钥；不要把聊天文本或供应商网页地址填在这里 |
| Base URL | 服务提供方要求的接口基础地址，不是官网登录页 |
| Model Name | 服务实际接受的模型标识，必须与你的账号权限和服务一致 |
| 温度 | 按任务设置生成的变化程度；先保留适用默认值，再按效果调整 |
| 最大输出 Token | 限制一次输出长度；它不是模型上下文窗口大小，不宜直接照搬上下文上限 |
| 视觉能力 / 思考模式 | 根据模型实际支持情况配置，打开开关不会让模型获得原本不支持的能力 |

模型访问条件、额度和计费由你使用的服务决定。首次配置先做小任务，确认能正常请求和返回，再处理长文档或多智能体任务。

### 3.3 使用本地模型

如果本机已经运行 Ollama、vLLM 或兼容接口服务：

1. 确认服务已启动，目标模型已在该服务中可用。
2. 在模型配置中填写正确类型、实际接口地址和模型名称。
3. 不要求认证的本地服务可以留空 API Key；要求认证时仍需填写。
4. 将智能体绑定到该模型并保存，再测试普通对话和所需工具能力。

当前源码对明确的 `ollama` / `vllm` 服务以及 HTTP/HTTPS 回环地址采用可选密钥策略。普通远程模型仍要求密钥；仅仅是内网地址不代表可以免认证。

本地模型是否能稳定调用工具，取决于模型和服务提供的协议能力。聊天成功后，仍建议用“读取一个测试文件并总结”验证工具调用。

### 3.4 使用环境变量保存模型密钥

熟悉配置文件的用户可引用环境变量：

```yaml
model_cfg:
  my_model:
    type: openai
    api_key_env: MY_MODEL_API_KEY
    base_url: https://api.example.test/v1
    model_name: your-model-id
```

这只是配置片段，地址与模型名必须替换，其他已有配置应保留。启动 macs 的进程需要能读取 `MY_MODEL_API_KEY`；变量未设置或为空会导致配置错误。

不要把真实密钥发到聊天中，也不要把带密钥的配置上传到公开仓库。向别人说明问题时，只提供脱敏后的配置项和错误信息。

## 5. 完成日常任务

### 5.1 一条好用的任务指令

说明以下四件事就足够：

| 要素 | 示例 |
| --- | --- |
| 目标 | 分析本月销售变化，找出三个主要原因 |
| 材料 | 使用我上传的表格，以“已完成订单”为统计范围 |
| 产物 | 输出一份中文 Markdown 报告和汇总 CSV |
| 约束与验收 | 不修改原始文件，标注缺失数据，给出生成文件的路径 |

例如：

> 请分析上传的销售表，以已完成订单为口径比较各产品本月与上月的变化。输出中文报告和汇总 CSV，保存到当前工作区的 outputs 目录。保留原始文件，说明缺失值与异常值的处理方法，并核对汇总数。

### 5.2 上传和发送

1. 点击 **新任务**，选择合适的 Agent。
2. 通过输入区的文件或图片按钮添加材料。
3. 等待附件上传完成，并确认界面中显示了正确文件。
4. 输入要求后按 `Enter` 发送；`Shift + Enter` 换行。

图片理解需要视觉模型支持。扫描版 PDF、音视频或特殊办公文件可能还需要 OCR、转录或转换依赖；如果提取失败，可以先提供可复制文本或转换后的文件。

### 5.3 运行时补充要求

任务进行中需要补充时，直接发送清晰的追加要求，例如：

> 补充：金额统一保留两位小数，汇总结果另存一份，不覆盖刚才的文件。

追加输入与停止任务是两种操作。正在执行的外部工具可能已经产生效果，补充要求通常在后续可处理输入的阶段生效；不要假定它能追溯撤销已完成动作。

需要结束工作时使用界面中的 **停止/取消** 操作，并在任务中心确认状态。停止会阻止后续执行，但不会自动撤回已经发送的消息或删除已经生成的文件。

### 5.4 查看进度和结果

从 **任务中心** 查看执行者、最新进展、状态及产物。出现长时间等待时，先看当前处于模型调用、工具执行、排队还是等待审批，再决定是否取消。

完成后检查三项：回答是否满足要求、文件是否能打开、关键结果是否经过核对。文件通常通过对话链接、任务产物或 **交付物** 访问，也可能保存在你指定的工作目录。打开 **交付物** 后，桌面左侧显示列表、右侧直接预览第一项的结果和附件；搜索或筛选会保留仍可见的选中项，否则选中新的第一项，没有匹配时清空预览。手机上直接显示选中项的预览，点击 **返回交付物列表** 可切换查看其他内容。

刷新或关闭浏览器不等于取消后台任务。页面断线后，应先查已有任务和历史记录，避免直接重发带外部写入动作的任务。

## 6. 使用和管理记忆

在 **设置 → 工作与记忆 → Agent 记忆** 中可开启或关闭记忆，默认开启。
点击“保存并应用”后，新任务使用新设置，无需重启；运行中的任务沿用原设置。
关闭后停止新任务的记忆召回与学习，已保存内容保留，仍可查看和遗忘。
各助手的“记住对话”开关受这个总开关控制。

这里的“记忆”是以前积累下来、以后可能用来回想和回答的内容：做过的任务、工具与 Skill 经验、反馈、偏好、学习知识和会话记录，都属于这条主线。你手工保存的记忆条目只是其中一部分。保存下来、能在页面看见、这次回答会引用，是三件不同的事。

普通 **Agent 模式**会按当前问题自动选择部分记忆；还可以在需要时搜索旧任务或学习经验。**简单问答**目前只带当前会话的问答消息，不读取 Agent 的长期记忆，也不调用记忆工具。图片、音乐等直接生成同样不会自动进入这条 Agent 记忆链路。

### 6.1 从提示词代码找到原有历史信息

点击侧栏 **记忆**，在当前页面弹出窗口，沿用当前助手和会话，保留主对话及输入内容。窗口支持最小化、最大化和关闭；关闭后重开同一上下文保留记忆编辑草稿。切换助手或任务时，若有未保存内容，先选择继续查看或明确放弃后再切换。

默认沿当前提示词组装代码显示原有历史信息。选择助手和会话，查看当前历史消息、记忆上下文和项目说明的原内容、保存位置，以及它们通过什么代码进入提示词。这里不要求先运行一个新任务，也不把所有数据库归档都列为记忆来源。

**直接加入** 指当前会话消息或项目说明的组装入口直接读取；**按问题召回** 指任务结果、经验、偏好、摘要等还要按当前问题、范围、预算和安全规则筛选。后续上下文压缩仍可能缩减内容。这些说明来自实际读取路径，不代表每条内容在某次回答中都已出现或被模型采纳。

展开 **查看某次实际调用**，才查看已录制请求中的 **本次提交的片段** 和 **当前来源内容**。工具查询的旧内容只有进入后续模型请求，才出现在那一轮记录中。旧调用没有记录时不能还原完整发送内容，但仍可从上面的代码读取入口找到现有原数据。

实际调用记录中的 **尝试发送** 表示开始提交，**已发送至模型** 表示收到成功 HTTP 响应，**发送失败** 表示请求失败或被拒绝。这些状态都不证明模型采纳了内容。记录只从之后的普通 Web Agent 调用开始产生；没有调用记录不等于数据库没有记忆。

打开某个来源后，可对支持管理的原数据选择 **更正** 或 **删除**。保存核对当前版本，发生冲突时保留草稿，先重新读取再核对。操作直接作用于原条目、会话状态、摘要、原消息、任务经验、学习知识、图谱事实或工作区内的说明文件；过去输入的摘录不会被重写。工作区外的说明及没有可靠可写定位的来源只读。

更正或删除不能撤回已提交的请求，也不会替运行中的任务改掉已经构造的上下文。需要取消当前任务后重新开始，才能核对重新读取的结果；其他派生记录仍需按其来源分别处理。

### 6.1.1 其他存储资料的七个分类

展开 **其他存储资料** 才进入原有分类浏览。这些内容是存储中的资料，部分不接入当前提示词读取路径，也不是某次模型输入的回执。左侧切换分类，右侧显示内容、来源和真实时间；手机上分类横向排列。

| 分类 | 内容和适用范围 | 如何管理 |
| --- | --- | --- |
| **短期记忆** | 选定会话的人工笔记、当前工作状态和自动摘要 | 人工笔记可新增、更正、遗忘；自动来源只读，可另存经验 |
| **长期记忆** | 当前助手保存的个人事实、决定、经验，以及任务沉淀的经验来源 | 搜索、筛选、编辑内容和确认候选；偏好单独查看 |
| **用户偏好** | 长期条目中类型为“偏好”的内容 | 更正偏好，少量重要偏好可设为常驻 |
| **项目记忆** | 当前工作区、当前助手的项目事实、约定和经验 | 新增项目笔记或更正内容 |
| **全局记忆** | 工作区共同说明、明确共享笔记，以及各助手已保存记忆的只读汇总 | 共享笔记可新增、更正、遗忘；其他助手记录保留原归属 |
| **知识库** | 任务学习知识、旧图谱关系与原文、已有上传资料库 | 按知识来源筛选、翻页；上传资料在原管理入口维护 |
| **历史任务** | 当前助手的最近 200 个已验证会话及原始消息 | 查看、继续对话，或把有价值的内容另存为经验 |

这些分类按用途查看原有资料，不会复制成多份数据。短期只看当前任务的工作状态与摘要，原始回答、反馈和工具过程在历史任务；个人偏好与项目笔记也分别查看。全局中各助手的只读汇总不会把其个人记录自动加入当前助手或转成共享记忆。历史任务、知识文档和自动摘要各自保留原数据。

记录时间来自真实数据。没有创建时间的旧工作状态或自动摘要显示“未记录”，不会用打开页面的时间补填。来源与版本可以展开查看。

已有任务结果、工具名称及成功状态、执行耗时、用户反馈和有原话依据的偏好会作为 **补充来源** 显示，标明原任务与时间。已保存记忆和本次读取的来源分别计数；来源仅在具有当前工作区、助手及会话归属证据时展示。没有执行记录的普通问答可显示真实回答摘录，不推测工具调用。你可以核对来源、修改结论后另存为记忆；查看页面不会调用模型或自动把历史记录确认成长期偏好。

**知识库** 中上传的资料与 **Agent 学习知识** 分开理解：后者来自原有知识记录，只有能对应到当前助手、用户和工作区的真实任务事件时，才作为只读来源展示。没有可靠来源的旧知识不会被强行归到你名下；查看也不会改变它的使用次数或自动确认成笔记。

知识默认先显示有来源的学习知识、原话核实过的会话事实和上传资料目录。需要查看积累的旧关系或原文时，再选择对应历史来源；全部来源中，同一原图谱记录只计一次，核实后的来源替换其旧归档显示。关系会分开列出主体、关系、对象和依据；有依据或置信度高仍不代表结论一定正确。标签沿用学习记录原有标签，核实引用只显示真正匹配到的原话。

旧图谱关系和旧原文可以按来源翻页查看。没有可靠个人归属的内容标为工作区旧资料、未核实，保留原位置和时间；它们不等于你认可的事实或偏好。涉及具体会话的资料仍需核对会话边界。上传资料库在这里显示名称、说明和已有数量；文档原文与管理操作使用 **上传资料管理**。共享 MySQL 或工作区外的数据库保留原管理权限，不在这里强行并入个人列表。

**全局记忆** 中还可查看当前目录的 AGENTS.md 共同说明，以及同工作区已加载助手的有效记忆。说明文件需回原文件修改，各助手条目只读并显示来源助手。核对后可以另存自己的结论；这不会修改原资料，也不会自动将其他助手记忆用于当前回答。

**用户偏好** 中还可查看旧工作区文件保存的历史偏好，标明来源位置、真实时间和“未核实”。与其他会话、工作区或已知外部身份有关的项不会并入；旧文件里的总条数也不等于这里的可见数量。你可以阅读核对后另存，查看本身不会把它们自动确认成个人习惯或改变会话记忆的范围。

展开 **查看资料来源**，可以了解历史经历、画像、学习知识等十种来源在哪里保存、怎样回想；再展开 **保存在哪里**，可查看数据库表名或工作区内的相对文件位置。这里的数量是本次核对范围内的数量，不是数据库总数；“数量未知”不等于没有记录，确认没有记录时才显示 0。

来源标为 **按问题自动回想**，表示 Agent 在条件满足时可读取相关内容；标为 **通过工具按需查询**，表示需要工具查询。未开启或还需运行时确认时，会给出相应提示。它们都不表示本次回答已经引用。展开这个目录只读取已有资料，不调用模型、不收费、不搬迁历史数据，也不会把旧记录自动确认成长期记忆。

这些内容的保存位置和回想方式如下。文件路径相对于当前工作区；使用 MySQL 时，“数据库表”指已配置数据库中的同名表，默认 SQLite 则在 `.openkitty/openkitty.db`。自定义数据库路径或目录应以实际配置为准。

| 以前积累的内容 | 保存位置 | 怎样让它回想 |
| --- | --- | --- |
| 做过的任务、调用过的工具和 Skill、结果与反馈 | 数据库 `memory_events`；原始消息在 `chat_sessions` / `chat_messages` | Agent 自动选部分相关经历；也可要求“查一下以前处理过的类似任务，说明当时的方法和结果” |
| 画像中的偏好、约束与学习知识 | 数据库 `user_profiles` / `knowledges` | 网页 Agent 参考核实过的偏好原话及有原任务来源的学习知识，不整份载入画像；学习知识也可按需查询 |
| 人工保存或确认的笔记 | 数据库 `memory_entries` | 有效且相关时参与自动召回；重要偏好可设为常驻，候选需先确认 |
| 当前会话状态与摘要 | `.openkitty/context/context.json`；数据库 `memory_summaries` | 选定任务时参考其工作状态，相关摘要可参与回想 |
| 图谱关系与依据 | `.openkitty/knowledge_graph.db` | 网页 Agent 只自动参考当前会话且原话依据可核对的相关事实；旧工作区归档供查看核实，不自动成为个人事实 |
| 上传资料 | 数据库 `rag_kbs` / `rag_chunks` 及原资料文件 | Agent 通过已启用的知识检索工具按需查找；看到资料目录不等于已读取正文 |
| 工作区共同说明 | `AGENTS.md` | 项目说明加载器按当前工作区读取；全局页展示它不会改变加载范围 |
| 学习经验文件 | `.claude/projects/E--openkitty/memory/*.md`，当前兼容目录名固定 | 不自动载入；Agent 可通过 `learn insights` 查询。仅生成学习报告并不等于已保存 |

网页 Agent 会先核对任务所属的用户、助手、会话、工作区和账号，再按本次问题挑选历史参考。其他聊天渠道保留原有记忆兼容规则，读取范围可能不同。来源面板分别说明“归属是否核实”“内容来自用户还是模型”“有没有原话或原任务”“符合哪些回想条件”；有效状态不证明内容正确，核实过的来源也不代表本次已经引用。

旧记录没有可靠归属时不会强行放进个人列表；页面空白也不代表整个数据库没有历史。需要核对原任务时，提供任务编号、主题和大致时间，再要求 Agent 查询。当前没有名为 `relook` 的工具；不要把“回想”理解成所有旧内容都会自动加入每次回答。完整技术分类见 [记忆来源与回想方式](architecture/memory-system-summary.md#memory-source-map)。

### 6.2 告诉它哪些需要长期记住

可以明确表达长期偏好：

> 请长期记住：以后给我写报告时，先给结论，再写依据；默认使用中文。

一次性要求则明确范围：

> 仅这次用英文输出，不改变我的长期默认语言。

当前请求中的明确要求优先于长期默认。并非每句话都会写入记忆，也并非每次回答都会加载全部记忆。查看管理页中的记录和状态，才能确认是否保存；高级参考记录可帮助判断是否被选入上下文。

### 6.3 查看、新增和编辑

以下操作位于 **其他存储资料**；管理这次已引用的原源则使用上述输入来源面板。

1. 选择分类和助手；短期记忆还需选择真实会话。
2. 搜索标题或内容，点击左侧卡片，在右侧查看完整信息。
3. 点击 **新增记忆**，填写标题、内容、范围和类型。全局分类保存到工作区共享范围；短期笔记仅属于选定会话。
4. 对已有人工条目使用 **更正** 修改内容。保存时核对版本，其他窗口已修改时会提示冲突并保留当前编辑草稿。
5. 自动摘要与原始消息不能在记忆页直接覆盖；需要长期保留的经验可另存为项目笔记。

例如：标题“报告风格”，类型“偏好”，内容“报告先给结论，再列依据，默认中文”。仅给当前助手使用时选个人范围；希望当前工作区所有助手使用时到全局分类手工新增。

人工条目保存后可参与真实记忆召回。标题、范围和类型在更正时保持不变；如需另一个范围，应明确新增对应笔记。保存失败保留草稿，取消后在同一页面重新编辑也能继续；尚未保存的草稿不会承诺刷新后仍存在。

### 6.4 确认、常驻和遗忘

| 操作 | 含义 |
| --- | --- |
| **确认生效** | 正确的待确认条目转为有效记忆；候选不会自动用于回答 |
| **设为常驻** | 有效个人或全局偏好优先参与参考，每个集合最多 5 条，仍受上下文预算限制 |
| **取消常驻** | 条目继续保留，按相关性参与召回 |
| **遗忘** | 确认后清空该记忆条目，并抑制旧内容被再次召回 |

更正后的内容如需继续常驻，要重新选择。遗忘不会删除原始聊天、历史文件、画像或知识库中的副本，不能当作“删除全部个人数据”。新建对话也不会清空长期记忆。

检索期间更正或遗忘条目后，旧版本会在进入提示词前的复核中被排除；新内容可在下一轮重新选取。该复核不会撤回已经发送给模型的内容。

### 6.5 导出和查看参考记录

- **导出长期记忆**：下载当前助手的有效个人、项目条目；在全局分类中导出工作区共享条目。短期工作状态、完整聊天和知识资料不包含在其中。
- **高级：查看记忆参考记录**：查看最近 7 天的 20 次召回元数据，了解来源、版本和选择原因；不记录问题或记忆正文，也不证明模型最终采用了该条内容。

导出文件按个人资料保管；这不是完整系统备份或一键恢复。某条信息没有影响回答时，核对工作区、助手、会话、状态及问题相关性；必要时在当前任务中再次明确要求。

此管理页属于本机个人工作区。企业多用户系统继续通过 AgentOS 的可信身份、用户隔离和工作区边界接入，不把平台钱包登录当作本机记忆的多用户认证。

## 7. 建立自己的知识库

适合长期重复查询的资料，例如产品说明、制度、业务流程或研究材料，可以放入知识库。

基本步骤：

1. 打开 **知识库**，或从工作台进入 **RAG管理**。
2. 创建或选择一个知识板块，用明确名称区分主题。
3. 在文档管理中选择板块，再上传文档。
4. 等待处理完成，查看文档与分块结果。
5. 进入 **RAG检索**，提出一个材料中有明确答案的问题，确认能找到正确片段。
6. 在相关任务中说明要使用的知识库；AI 员工如需自动检索，应配置对应知识板块。

当前上传入口支持 TXT、Markdown、PDF、DOCX、CSV、XLSX、HTML 等格式，实际解析效果取决于文件内容及运行依赖。扫描件可能需要先 OCR。

同一知识板块上传同名文件会按现有流程更新版本，更新前保留自己的原稿。上传成功并不等于每个问题都能准确命中；用检索测试检查关键内容更可靠。

当回答缺少依据时，可以要求：

> 只根据指定知识库回答，标出引用材料；找不到依据时明确说明，不要用猜测补齐。

## 8. 生成文档与填写 Word 模板

### 8.1 自由生成报告、表格或演示文稿

直接在任务中指定目标格式、内容结构和保存位置。例如：

> 用上传材料生成一份中文报告，包含摘要、证据、问题和建议。先生成 Markdown，确认内容后再导出为 Word。引用信息缺失时标出待补充项。

需要 PDF、PPTX 或复杂 Office 文件时，先让 Agent 检查对应生成、转换与预览依赖。文件生成后应打开核对；内容完整不等于分页、字体和版式一定符合预期。

### 8.2 用文档自动化填写现有模板

适合固定报告、检验记录、企业表单等“版式已确定，只更新内容”的工作。

1. 从 **工作台 → 文档自动化** 进入页面。
2. 上传 `.docx` 格式的 Word 模板。
3. 上传 JSON/CSV 数据，等待模板字段和数据来源识别。
4. 核对字段映射，处理缺失项、歧义项及重复表格行。
5. 点击 **生成预览**，检查填写位置和主要内容。
6. 确认后点击 **生成文档**，再使用 **下载结果** 保存文件。
7. 如需重复使用，可启用 **生成后保存此方案**；下次选择对应方案并换入新数据。

模板没有标准占位符时，系统也可以依据下划线、可填写书签、内容控件或表格结构提出映射建议；建议需要核对，不能只看“匹配成功”。

例如，模板中需要报告编号、委托单位和多行样品数据，可以提供：

```json
{
  "report_no": "DEMO-001",
  "customer": "示例单位",
  "samples": [
    {"sample_no": "S-001", "item": "外观", "result": "示例结果"},
    {"sample_no": "S-002", "item": "外观", "result": "示例结果"}
  ]
}
```

这是结构示例，不代表真实检测数据。重复表格行要确认数组和模板行的对应关系；材料中没有的数值应留空或标为待补充。

保存的方案记录字段对应关系和模板结构，不应保存本批次样品值。模板结构改变后，应重新检查映射。页面预览也不能替代最终在 Word/WPS 中检查分页、溢出、单位及结果口径。

## 9. 使用技能、AI 员工与多智能体

### 9.1 使用技能

从 **工作台 → 技能管理** 查看当前已安装技能。需要明确使用某个技能时，在输入框键入 `@`，选择实际存在的技能后描述任务。

技能会指导当前 Agent 如何开展工作，但不保证其所需的命令、模型或第三方服务已经配置。启用后提示依赖缺失时，先处理具体依赖再继续。

技能管理支持远程搜索及相应安装入口。远程市场的轻量安装只下载并校验技能说明，不等于同时安装全部脚本与运行环境；使用前查看技能说明和来源。

### 9.2 使用 AI 员工

从侧栏 **AI员工** 选择已有岗位，核对其模型、职责、知识板块和关联工作流。也可以在支持的输入入口用 `@员工名` 指定实际存在的员工。

例如：

> @资料整理员 请整理上传的产品资料，生成一份带来源的问答清单，并列出资料中没有覆盖的问题。

“资料整理员”仅为命名示例，需要替换成当前员工列表里的名称。模型未配置、岗位被禁用或缺少必要工具时，应先修正对应配置。

### 9.3 使用项目专家团队和多 Agent

适合任务可明确分工、需要交叉检查的场景：一个 Agent 整理证据，一个做分析，一个复核结论。

团队模板以卡片展示，宽屏每行五张，小屏自动减少列数。卡片列出用途、协作方式和成员。点击 **新增团队** 可以创建自己的团队；点击卡片上的 **修改**，在独立窗口编辑成员名称、职责和 Skill。保存会写入当前 macs 配置，重新打开或重启后仍可使用。团队名称也是调用标识，保存后保持不变。

新团队默认并行工作后汇总结果。内置团队保留原有协作方式；全栈和竞对团队按固定阶段执行，只能编辑成员职责，保留人数和顺序。编辑窗口可以增加或移除其他团队的成员。已有成员模型配置会保留。保存遇到版本冲突时，草稿不会丢失，需先检查最新配置再决定保留草稿或载入最新成员。

点击 **使用团队（Agent）** 会切换到 Agent 模式，并把团队说明追加到当前输入框，补充实际任务后再发送。已有草稿、附件不会被替换，也不会自动发送。图片、音乐等生成模型需先切换到文字模型，才能使用专家团队。

1. 打开 **项目专家团队**，或切换到多 Agent 配置。
2. 选择参与者和协作方式。
3. 为任务写清共同目标、每人的分工和最终交付格式。
4. 设置合适轮次及失败处理方式后执行。
5. 在执行记录中核对各方结果，再检查最终汇总。

协作方式包括顺序执行、自由讨论、投票或有主持的讨论等，具体选项以界面为准。多 Agent 会增加模型调用和等待时间；简单修改通常用一个 Agent 更直接。

**全部任务** 的任务编号单独成列，可以选择文本或点击复制按钮。搜索支持任务编号；没有真实任务编号的记录显示 **—**。复制不可用时会选中编号，方便手动复制。任务、工作流、AI 员工和定时工作分别显示各自的执行编号。

## 10. 工作流与定时工作

### 10.1 使用工作流

当一项工作稳定包含“收集 → 分析 → 核验 → 生成”这类步骤时，可以使用工作流。

工作流模板以卡片展示，宽屏每行五张，小屏自动减少列数。卡片显示步骤摘要、分类和审批等标记；点击后打开任务输入窗口，确认任务描述后才会启动。弹窗统一使用淡遮罩，保留后面工作区的可见性。

初次使用先打开工作流中的 **使用说明** 标签，了解用途、适用场景、周报流程设计示例和操作步骤，再选择模板。工作流相当于给 AI 一份固定的办事流程：方便重复使用、减少遗漏核对环节，并查看每步的进度和结果。模板可以包含分支、循环或并行；可以为步骤指定工具，未指定时按系统权限使用工具。带审批的步骤完成并产出结果后才会暂停，批准后继续；如果发送、发布等动作需要提前确认，应放在审批步骤之后。每一步的 AI 判断仍需核对。说明页也提供返回模板列表及打开编辑器的入口。

1. 打开 **工作流**，选择已有模板或管理自己的流程。
2. 查看步骤需要的输入、执行者和输出要求。
3. 提交任务说明与材料，开始运行。
4. 在 **执行记录** 查看当前步骤、错误与结果。
5. 有审批节点时进入 **待审批**，核对具体动作后作出决定。

流程能否重试或恢复取决于步骤定义和已有执行状态。遇到外部写操作结果不确定时，先核验外部系统，不要把恢复等同于“整条流程无条件重跑”。

### 10.2 创建定时工作

从 **工作台 → TODO** 打开定时任务管理，在创建入口填写任务内容、选择 Agent，并设置界面支持的执行时间。

保存后检查任务是否出现在列表，时间是否符合预期。不要仅凭聊天中的“明早提醒我”就认为定时任务已经创建；以实际任务记录为准。

macs 进程必须在计划执行时保持运行，电脑休眠或服务停止会影响执行。第一次设置定时工作，先用短小、容易核对结果的任务试运行。

## 11. 权限、计划与执行

普通模式下，已经允许的工具可以连续执行，不必对每个常规步骤重复确认。

需要先看方案时，可以直接说：

> 先检查并给出方案，这一步不要修改文件，等我确认后再实施。

需要直接完成时，可以说：

> 按上述要求实施，常规细节自行处理；完成后运行检查并交付结果。

计划模式限制写入动作，适合调查和方案整理。旧界面或配置中的 `default`、`acceptEdits`、`bypassPermissions` 是兼容模式名，“全部放行”之类显示不意味着可以突破工作区、租户、危险命令或明确禁止的边界。

权限查询工具用于查看状态、列出规则和提出建议，不让 Agent 自己扩大宿主权限。遇到确实需要审批的工作流或工具，按界面的具体审批请求处理。

不要为了让普通任务执行而额外添加 `--dangerously-skip-permissions`；当前保留该参数用于旧启动方式兼容，普通工具本来就不需要逐项确认。

## 12. 接入渠道、工具和外部系统

### 12.1 聊天渠道与外部工具

点击侧栏 **skill知识技能 · 连接 → 连接应用**，或进入 **设置 → 连接应用**，配置已支持的聊天渠道，填写对应参数并启用，再用一条测试消息确认收发正常。不同渠道的账号、应用和回调配置不同，不能只打开开关就认为接入完成。

MCP 可用于连接外部工具服务，具体启动命令、地址和凭证需要与该服务一致。浏览器、桌面自动化及外部编程 Agent 也有各自依赖；让 macs 先检查能力状态，再执行真实业务操作。

对已经成功完成的重复界面流程，可进一步使用工作流学习能力整理为参数化技能。复用时仍要检查页面结构和结果断言，不能假定网页变化后仍可按旧坐标执行。

### 12.2 作为 AgentOS 后端

已有业务系统可以通过 AgentOS 异步调用 macs：提交任务后先取得任务 ID，再查询状态、订阅进度和获取结果。

右上角 **帮助** 提供四个文字导航：**配置模型、开始对话、个人助手、接入AgentOS（企业智能后台）**。点击在当前帮助窗口中跳到相应说明，AgentOS 导航同时展开部署教程。个人助手中的“本机启动、移动办公和脚本检查”说明 Windows 双击启动、页面模型配置与连接应用。初始模板允许进入 Web 设置；默认的本地模型候选仍需安装并启动，不能把成功打开页面当作模型已可用。移动办公时 macs 所在电脑须持续运行。

帮助中的 **检查本机服务** 只查询健康状态和可用助手，不提交任务或扣费。也可下载 Python 脚本，使用 `--local --url http://127.0.0.1:实际端口` 检查本机兼容模式；已启用认证时仍需有效凭证。后台 API 调用不继承网页登录，使用自定义模型密钥、平台访问密钥或已运行的本地模型。未单独选择模型的助手继承当前文字模型，任务接受后冻结所用模型，切换模型不改变已接受任务。

**AgentOS 接入** 先区分简单问答、页面 Agent 和业务 API：AgentOS 复用同一个 Agent 运行时，供网站或其他业务系统提交持久任务。部署模式默认 `all` 同时接收和执行；`gateway/worker` 用于拆分部署，与对话方式不同。部署教程说明岗位与服务凭证配置、服务器启动、Python 调试、调用、Skill、多用户身份和审批。先在 **我的助手** 配置可用 Agent，在 `openkitty-config.yaml` 的 `service_roles` 发布岗位，为调用方配置 `service_clients`；合并监听配置后重启 macs。未配置独立监听器时使用主监听端口，配置 `gateway.agent_os_listen_addr` 后使用独立 AgentOS 地址。PowerShell 临时变量不传给另外双击启动的进程；实际配置路径按当前工作目录和用户配置目录查找。

从受信业务后端携带 `Authorization: Bearer <service-client-token>` 调用 `GET /api/v1/agent/roles`，选择岗位后向 `POST /api/v1/agent/tasks` 提交 `role_id` 与 `message`。用响应的 `links.self` 查询任务快照，或用 `links.events` 订阅 SSE。服务凭证保留在业务后端；它与付费模型服务的账号访问密钥用途不同。

企业自部署由自己的业务系统调用自己的 macs 服务，可以使用自行配置的模型服务。帮助中的 **可选示例：接入 SICurrent 平台** 提供 `[openkitty]` 两端配置、用户身份映射、原生任务接口与账号外壳的差别，以及可下载的 `sicurrent_agentos_check.py`。该脚本默认只读取元信息和岗位，显式 `--submit` 才创建真实摘要任务。平台会话响应 `201` 必须带 `task.id` 才表示任务提交；无编号时可能只是保存消息。平台的 `/api/macs/v1` 是模型和扣费服务，不能填成 AgentOS 任务地址。

SICurrent 账号任务接口当前并未对所有角色统一扣费；任务用户 ID 控制数据归属，底层平台模型访问密钥决定模型费用归属。SSE 只展示进度，仍需回查任务快照；结构化岗位结果、外壳审批和客户幂等重试有现有限制。配置与调试完整示例见 [AgentOS 快速指南第 6 节](./agentos-quickstart.md#6-可选示例sicurrent-平台接入)，原生契约见 [AgentOS API](./agent-os-api.md)、[企业服务接入](./enterprise-agent-service.md) 和 [OpenAPI](./openapi-agentos.yaml)。

| 阶段 | 调用方应该做什么 |
| --- | --- |
| 提交 | 使用已配置的服务身份和岗位，携带稳定的幂等键 |
| 接收 | 新任务通常返回 `202` 与 `task_id`；不要把“已接收”当成“已完成” |
| 等待 | 查询任务快照，需要实时进度时订阅任务 SSE |
| 追加/取消 | 使用已有任务 ID 调用相应入口，避免重复提交整个任务 |
| 结束 | 检查终态、结果和产物；断线后以持久任务快照为准 |

常见状态为 `pending`、`running`、`waiting_approval`，终态包括 `completed`、`degraded`、`failed`、`stopped`。`degraded` 表示存在降级或部分结果，应核对说明后再采用。

### 12.3 多个用户怎样区分

个人本机 Web 工作台不能直接当成完善的多用户账号系统。需要让同一后端服务多个用户时，应使用受信业务后端认证用户，再按 AgentOS 配置传入稳定的用户身份。

服务调用方按要求配置 `users:act_as`、`require_user_id` 等能力，并使用 `X-OpenKitty-User-ID` 传递已认证的用户标识。系统据此区分任务、会话、记忆和个人工作区；换一个会话 ID 不能替代换用户身份。

服务 Token 留在业务后端，不直接交给终端用户。远程部署也不要把普通 Web 管理面直接当成用户隔离层。

完整配置与接口示例见 [AgentOS 接入快速指南](agentos-quickstart.md) 和 [企业服务配置](enterprise-agent-service.md)。普通个人使用不需要配置这部分。

## 13. 配置、数据与备份

### 13.1 当前用的是哪份配置

未显式指定时，程序按以下顺序查找，找到后停止，不自动合并多份配置：

1. `--config` 或 `-c` 指定的文件。
2. 当前启动目录的 `openkitty-config.yaml`。
3. 当前启动目录的 `.openkitty/openkitty-config.yaml`。
4. 用户目录的 `~/.openkitty/openkitty-config.yaml`。
5. 均未找到时，尝试生成用户目录中的默认配置。

`--path` 指定工作区，`--config` 指定配置，两者不要混淆。要让项目配置明确独立，可以复制随包模板并显式启动：

```powershell
Copy-Item .\openkitty-config.template.yaml .\openkitty-config.yaml
.\openkitty.exe --config .\openkitty-config.yaml --path . --port 8090
```

复制命令只用于尚未创建实际配置的目录；已有配置时直接编辑，避免覆盖。Linux/macOS 可使用对应的文件复制命令和 `./openkitty` 启动。

### 13.2 哪些数据需要保留

| 内容 | 常见位置或查找方式 |
| --- | --- |
| 实际配置 | 以启动日志和设置显示的配置路径为准，可能含密钥 |
| 本地数据库 | 默认工作区 `.openkitty/openkitty.db`；可能被数据库或环境配置覆盖 |
| 记忆与运行状态 | 工作区 `.openkitty/` 及配置指定的其他数据目录 |
| 用户技能 | 实际安装或配置的技能目录；与程序内置技能区分 |
| 文档复用方案 | 工作区 `.openkitty/document-templates/` |
| 原始材料和生成文件 | 你指定的材料目录、输出目录及系统存储目录 |

使用 MySQL 或外置 SQLite 路径时，仅复制工作区并不构成完整备份。使用了自定义记忆、技能或输出目录，也要一并保留。

### 13.3 备份与恢复

建议按以下步骤做一次完整备份：

1. 等待重要任务结束，或先确认其当前状态。
2. 停止 macs 服务，避免复制正在变化的本地数据库。
3. 备份实际配置、整个工作区数据目录、原始材料、产物及自定义技能目录。
4. 如使用外部数据库，另外按数据库自身方式完成一致性备份。
5. 在备份中记录程序版本、配置位置、工作目录及备份时间。

恢复时先保存当前现场，再把配置和数据放回对应位置，使用正确的 `--config`、`--path` 启动。先检查历史记录、记忆和一个小任务，再恢复定时任务或批处理。

不要只备份程序文件，也不要把记忆导出 JSON 当作完整备份。

### 13.4 升级与退出

升级前停止服务并备份数据；保留旧程序，在单独目录解压新包，再让新程序使用原有配置和工作区。新包中的模板不应覆盖你的实际配置。

升级后先查看 `--version`，再验证模型请求、文件读取和一项代表性任务。新程序已经调整数据库结构时，不要假定旧程序能直接使用更新后的数据；需要回退时应结合升级前的程序与备份处理。

可以通过界面 **退出系统** 或终端 `Ctrl+C` 结束服务。关闭浏览器标签页只是离开界面。

## 14. 常见问题

| 现象 | 优先检查与处理 |
| --- | --- |
| 浏览器打不开 | 程序是否仍在运行；终端实际监听端口是什么；是否访问了 `/web` |
| 双击后窗口消失 | 在终端运行程序，保留并阅读退出前错误，不要反复双击猜测 |
| 明明启动了却访问不到 8090 | 模板可能使用 8080，端口也可能因占用而变化；以日志为准，必要时显式使用 `--port` |
| 模型配置保存了但仍用旧模型 | 智能体是否绑定到新模型配置名；是否点击了“保存并应用”；必要时结束任务后重启 |
| 提示 API Key 或环境变量错误 | 云端密钥是否有效、变量是否传入启动进程；本地模型类型和实际地址是否正确 |
| 本地模型仍提示缺少密钥 | 核对所用构建是否包含本地辅助调用修复；旧二进制不会随源码修改自动更新 |
| 对话可以用，但工具不会执行 | 模型是否支持工具协议，工具是否启用、是否缺依赖，是否处于计划模式或有明确限制 |
| 文件读不到或写到别处 | 当前工作区、文件路径和 `--path` 是否正确；远程 AgentOS 任务有独立个人工作区 |
| 记忆没有显示 | 是否选择了正确 Agent 和工作区；状态/范围筛选是否隐藏条目；内容是否实际保存 |
| 记忆更正提示冲突 | 先刷新条目再修改，避免用旧版本覆盖后续更新 |
| 远程打开记忆页被拒绝 | 个人记忆管理接口限制本机使用；多用户访问需要相应的认证管理入口 |
| 知识库上传成功但答不出来 | 先做检索测试，检查提取文本、板块绑定、分块和问题关键词 |
| Word 映射错误或漏填 | 核对字段来源、重复行和未匹配项；模板变化后重新检查方案 |
| PPT/PDF/音视频生成失败 | 查看缺失的转换、渲染、字体或媒体依赖，不要把所有失败都归为模型问题 |
| 任务看似停住 | 查看任务阶段、心跳、日志、队列及待审批状态；确认后再取消或重试 |
| 停止后文件仍然存在 | 停止不等于回滚；先核对已产生的文件或外部动作 |
| 配置突然变回初始状态 | 查看是否发生配置恢复，以及日志提示的 `.broken-*.bak` 备份；修正备份内容后再恢复 |
| 多 Agent 又慢又重复 | 减少参与者、限制轮次、写清分工，或改为单 Agent 完成简单任务 |

反馈问题时，提供版本、操作系统、启动方式、相关任务 ID、复现步骤和脱敏错误。不要直接发送真实配置、密钥或包含个人资料的整份数据库。

## 15. 可直接使用的任务示例

替换下列材料名称、路径和目标后即可使用。实际能否完成取决于当前模型和已启用工具。

### 资料整理
