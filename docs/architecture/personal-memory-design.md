# MACS 个人版记忆系统设计

状态：长期设计提案，部分落实。当前已有统一记忆服务、手工与 durable 上下文的数据库权威集合、
有界自动召回、候选状态、版本更正、删除保护、数据库摘要和持久后台处理。生产工具的长期写入已按本轮用户原文做保守的明确指令/原样值校验，并保存有限来源引用；完整证据链仍未实现。
具体运行与迁移边界见 [memory-service.md](memory-service.md)。
本文完整证据血缘、持久向量索引、跨存储完全遗忘与多用户管理仍是后续目标；本机记忆管理界面已实现，
不能将完整提案描述为当前已实现能力。

## 产品目标与技术选择

个人版优先保证记得准确、能解释来源、能纠正、能忘记，并保持本地安装简单。
默认沿用 Go 运行时和本地 SQLite，不要求额外部署 Python 服务、图数据库或向量服务。
向量模型可以使用已有本地或远程 embedding 能力；本地存储不等于模型处理完全离线。
关键词召回应在 embedding 未配置或不可用时仍然工作。

设计借鉴 Letta 的常驻与按需记忆分层、LangMem 的提取与整合，以及 Basic Memory
的可读性。它们是设计参考，不作为个人版默认运行依赖。Mem0 可以作为后续可选
外部后端和对照评测对象，不进入本阶段默认安装路径。

## 当前实现与差距

| 当前入口 | 已有能力 | 本方案需要补齐 |
| --- | --- | --- |
| `internal/memory/service.go`、`service_tool.go` | 数据库权威记录、范围、候选/有效/删除、版本纠正、统一召回与旧数据导入 | 完整逐消息证据、跨 Agent 共享与语义血缘 |
| `internal/memory/store.go` | 任务事件、画像、历史检索、关键词与向量融合 | 区分历史记录与确认事实，持久向量覆盖完整记忆集 |
| `internal/memory/deriver.go`、`processing.go` | 有原文证据的图谱事实、持久任务、重试与取消 | 图谱与规范集合的完整派生关系 |
| `internal/memory/knowledge_graph.go` | SQLite 三元组、时间有效性、原文存储 | 身份/范围合同、事务修订、多值关系语义 |
| `internal/memory/session_extractor.go` | 独立会话进度、数据库摘要、入队修订与有效租约保护、相关召回 | 更完整的历史摘要覆盖与语义检索 |
| `internal/memory/artifact_preferences.go` | 长期产物格式偏好，当前请求优先 | 保持兼容，防止新旧偏好存储成为两个事实来源 |

当前 `agent_memory` 的 user/project 都仍受个人 workspace 和 Agent 命名空间约束，不能
在迁移中默认为个人全局。不同 Agent 之间的共享也必须显式建立规则。

## 记忆分层

| 层 | 示例 | 写入与读取规则 |
| --- | --- | --- |
| 当前工作状态 | 本次任务进度、待办、临时输出要求 | 仅当前 session，随会话恢复，不自动晋升 |
| 稳定偏好与事实 | 长期输出语言、经确认的项目约定 | 证据充分或用户显式记住；按身份和范围召回 |
| 事件与经验 | 完成某次任务、某操作失败及原因 | 按需召回；结论与当时证据一起保留 |
| 历史与证据 | 原始用户消息、工具回执、transcript | 支撑追溯，不全部注入 prompt |

只有少量已确认的稳定偏好进入常驻上下文，其余按请求召回。记忆不授权工具动作，
历史产物路径不证明文件仍存在，历史外部系统状态不能当作当前状态。

## 身份、范围与策略

所有读写由宿主构造可信身份：tenant、稳定 user ID、workspace、Agent namespace、
session。模型参数不能改变这些身份。显示名不能单独作为跨渠道合并用户的依据。
无法确认用户映射时维持原范围，不自动合并。

第一版维持当前 workspace 隔离：user 表示此 workspace 内用户偏好；project
表示此 workspace 内项目事实；session 仅原会话可见。跨项目个人画像后续单独
设计身份绑定与用户可见的分享设置。旧 Agent namespace 默认保持私有。

记忆策略分别管理 recall、explicit_write、automatic_capture。总开关关闭时三者
都停止；查看、导出和删除已有记忆仍可用。关闭记忆不等于清空聊天历史，也不
影响任务执行所必需的 checkpoint。暂停自动提取时，仍可以允许显式“记住”。

策略更新后，后台任务在取任务、调用模型前、提交结果前分别复查当前策略与范围。
已经运行的任务不得在关闭后偷偷提交新记忆。

## 统一数据合同

采用一个规范记忆集合，现有事件与 transcript 继续作为证据层。规范集合使用
本地 SQLite 事务存储，连接、迁移与生命周期由 app 注入。确定实际数据库路径
前核对现有 KG 与应用数据库的初始化，不额外创建一套未受宿主管理的数据库。

以下是目标字段与表职责，尚非已发布 Schema：

| 数据 | 必要字段/职责 |
| --- | --- |
| `memory_entries` | id、tenant/user/workspace/namespace、scope/session、kind、key、content、status、revision、valid_from/to、expires_at、created/updated_at |
| `memory_evidence` | memory id、source type/id、message/tool receipt id、原文引用、角色、源时间；支持一条事实多条证据 |
| `memory_relations` | supersedes/derived_from/supports 等血缘；用于纠正、删除与防止复活 |
| `memory_jobs` | 源范围、源消息区间、任务类型、状态、幂等键、attempt、next_run、lease/fencing、错误分类、策略代数 |
| `memory_embeddings` | entry id/revision、model/provider 标识、dimension、vector、生成状态；不能混用不同模型空间 |

status 至少区分 candidate、active、superseded、expired、deleted。模型给出的
confidence 只用于候选排序，不能代替证据校验或用户确认。

`UserProfile.Constraints.artifact_format_preferences` 保持现有合同。迁移前它仍
是产物格式偏好的权威来源；统一服务通过适配读取，不能另写一份相互竞争的偏好。
只有完成原调用者切换与兼容回写协议后，才能迁移其权威存储。

领域规则、存储、检索与队列位于 `internal/memory/`；app 只做身份绑定、依赖注入
与生命周期。通过窄接口暴露 Capture、Recall、Correct、Forget、List、Policy；
继续使用现有 `agent_memory` Tool 与 Tool Registry，不新增平行工具发现体系。

## 写入与整合

显式“记住”经策略和范围校验后，保存 active 记录及原始用户消息证据。一次性
要求只用于当前任务，除非用户明确要求长期保存。不得自动保存模型推测的性格、
职业、健康等个人结论；本阶段自动记忆只覆盖有用户原文支撑的稳定事实与偏好。

自动提取流程：

1. 从已持久化的消息范围创建幂等提取任务；前台无需等待模型提取。
2. Worker 使用宿主 context、超时和可恢复租约读取原始消息，保留角色与顺序。
3. 模型输出候选事实、范围建议、对应消息 ID 和原文证据。
4. 校验引用确实存在且属于该用户/范围；AI 回答不能单独证明用户事实。
5. 排除一次性要求、虚构/引用文本、提示注入与无证据推断。
6. 明确的稳定陈述可按策略进入 active；歧义或冲突保持 candidate，不进入常驻上下文。
7. 在事务内提交记录、血缘和索引任务，再推进已处理消息水位。

跨数据库的消息持久化与任务入队不能声称是一个原子事务：使用源消息幂等键和
可恢复扫描水位补偿遗漏。成功水位只在提交后前移；失败重试有上限，永久失败
可查看并重新触发。忙碌时排队，不直接丢弃整轮提取。

## 纠正、多值与删除

纠正通过 entry id 或明确的结构化 key 定位；不能模糊删除某个词匹配的所有事实。
单值属性采用 supersedes 关系关闭旧版本，新版本与旧版本在同一事务提交。
多值关系允许并存，例如“使用 Go”和“使用 Python”；不同 object 不构成自动纠正。
未识别的关系默认按多值处理，只有验证过的属性基数允许自动替换。

用户明确纠正优先于自动候选；仅仅出现更新日期不代表新内容正确。当前请求中的
明确要求优先于长期默认；会话状态、项目事实和用户偏好仅对同一属性产生可定义
的覆盖，不使用一个任意全局分数决定事实真伪。

遗忘先在事务中标记 deleted、清除证据内容、索引负载与派生项，并使旧版本不可
召回，再清理缓存和旧存储投影。保留不含原文的最小删除标记，阻止重放任务和
旧 JSON 导入复活记录。事实的独立证据要单独判断，避免删除一个来源误删其他
仍有效的事实。

“删除记忆”与“删除聊天历史”分别说明；保留原始会话时，需要禁止自动提取再次
从被遗忘的源区间重建对应事实。已经进入本轮模型上下文的内容无法从已完成的
模型调用中撤回；删除返回后所有新召回与后台提交必须反映删除状态。

## 检索与注入

先执行身份、namespace、scope、status 与有效时间过滤，再检索和排序。第一版
以 SQLite 关键词检索为基础，探测 FTS5 可用性，保留可工作的关键词降级路径。
向量在写入后异步生成并持久化，不能只扫描最近几十条事件或每次重新计算历史向量。

关键词与语义结果使用融合排序、去重和上下文预算。当前稳定偏好、小量相关项目
事实、相关事件分别分配预算；首次目标总预算 2,000 tokens，可配置，并用实际
评测调整。返回 memory id、revision、来源摘要和有效时间，便于回答与排障。
只有用户询问历史时才召回被替代的历史版本，并明确其当时有效时间。

记忆作为带来源的数据注入；其中的文字不能提升为 system 指令或绕过权限。
查文件是否存在、某任务是否完成等问题仍走当前工具或持久任务快照验证。

## 用户界面

在现有设置/工作台提供记忆入口：按范围与状态浏览、搜索、查看来源、编辑、删除、
处理候选冲突、暂停自动记忆及导出。页面复用统一记忆服务，不直接读写 JSON/KG。
删除成功必须意味着召回已阻断；异步清理尚未完成时显示准确状态。
导出使用用户可读 JSON/Markdown，索引仍是派生数据，不能把导出文件当第二份权威库。

## 分阶段实施与验收

| 阶段 | 交付 | 必须通过的验收 |
| --- | --- | --- |
| P0：策略与身份 | 全路径统一开关，可信身份合同，现有手工范围接入 | 关闭后无自动读写；不同 session/workspace/user 无泄漏；当前要求覆盖长期默认 |
| P1：事实生命周期 | 事务存储、证据、候选、纠正、删除、旧数据迁移 | 无证据不晋升；多值共存；纠正后默认只返回新值；删除后重启/重放不复活 |
| P2：可靠处理与召回 | 持久任务、重试、成功水位、持久向量、预算检索 | 提取崩溃可恢复且不重复；旧事实仍能召回；embedding 故障关键词可用；旧 revision 不覆盖新索引 |
| P3：可见管理 | 来源查看、候选管理、编辑/删除、导出与诊断 | 前后端行为一致；用户能解释某条记忆从何而来；主链路端到端验证 |

迁移先备份并报告范围，按原文件地址和记录版本产生幂等导入 ID；旧记录缺少身份
或来源时隔离，不能推断成全局。分模块切换读路径后再停止旧写路径，禁止长期
无协调双写。旧文件保留用于恢复，不自动删除用户数据。回退必须保留删除标记
与修订水位，不能回退到会重新召回已删除事实的旧读路径。

评测集至少覆盖：稳定偏好、一次性要求、跨会话恢复、用户纠正、多值关系、
过期事实、同名不同用户/项目、AI 幻觉、引用文本、提取失败、删除后重放，以及
10,000 条以上记忆中的早期事实。统计召回正确率、错误晋升率、删除残留、上下文
token 和读写延迟；与当前基线使用同一模型、同一请求及同一预算比较。

实施时先记录现有 `internal/session` 测试导入环及 memory 摘要断言失败。每阶段
运行就近测试和 `./cmd/macs` 主程序构建；已有迁移失败与新增失败分开报告。
