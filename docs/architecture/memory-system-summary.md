# macs 当前 Agent 记忆系统总结

整理日期：2026-10-13。正式产品名为 macs，小名为 openkitty。

本文描述当前源码中的实现，不代表未来设计或完整的端到端验证结果。详细实现约定见 [记忆系统说明](memory.md)，后续方案见 [个人版记忆设计](personal-memory-design.md)。

## 1. 总体结论

本项目中的“记忆”统一指：过去积累下来、以后可能被召回并作为上下文进入模型提示词的内容。它包括任务经历、可复用的工具与 Skill 经验、反馈、偏好、学习知识、会话状态和已确认条目，不只指 `memory_entries`。保存、管理页面展示、按任务召回是不同环节；已保存的内容不会全部进入每次提示词，原始记录也不自动成为已确认事实。

管理窗口现在默认从**实际提示词组装代码**反查已存来源：会话历史、统一记忆上下文和真实项目说明加载入口，分别标明直接加入或按问题筛选，再读取、更正或删除对应原记录。无需再发一次模型请求，也不把归档目录或新录制的回执当作所有记忆。分类只帮助找到这些来源；某次调用的实际发送片段另行查看，才用于核对该次请求是否保留了内容。这两层都不测量模型是否采纳或依靠它作答。

当前记忆系统已经具备保存历史、学习偏好、跨会话召回、手工管理记忆和 AgentOS 多用户隔离的基础能力。数据主要保存在现有应用数据库及本地 JSON、Markdown 文件中，不需要另外部署独立记忆服务。

当前已增加统一 `MemoryService`：手工记忆与 durable 上下文使用同一数据库权威集合，普通回合统一召回，摘要和事实提取使用持久任务。实现与迁移契约见 [统一记忆服务](memory-service.md)。画像、图谱与证据层仍有独立存储，**删除一条长期记忆不代表所有原始记录都已清除。**

生产工具的长期写入现在核对宿主冻结的用户本轮原文：明确的记住指令且其负载与写入值完全一致才立即生效；其他写入先成为候选。条目保存来源类型、任务引用和最短必要原文，候选确认另记录确认引用。此校验不覆盖独立的画像推断与图谱派生，也不能代替完整证据血缘。

## 2. 当前组成

| 部分 | 实现 | 保存内容 | 当前读取方式 |
| --- | --- | --- | --- |
| 历史事件与用户画像 | `MemoryStore` | 问答、工具执行信息、用户画像、偏好、约束、统计与知识条目 | 网页按核实归属的独立来源参考；其他渠道保留旧历史/画像兼容适配 |
| 记忆条目 | `Service` / `agent_memory` | 偏好、事实、决定、经验及候选，原 user/project/session 及显式手工 global | 数据库保存、版本更正与删除；同工作区所有者的共享条目进入统一有界召回，模型工具不能写 global |
| 持久上下文 | `session_context` / `SessionContextManager` | 会话工作状态及显式长期上下文 | durable 进入同一长期集合；SCM 自动读取当前会话项 |
| 知识图谱 | `KnowledgeGraph` / `Deriver` | 实体关系、来源、有效期及部分原文证据 | 网页只自动参考当前合法会话且原话证据核实的事实；工作区旧资料展示不增加召回资格 |
| 会话摘要 | `SessionMemoryExtractor` / `Service` | 数据库中的增量总结、入队修订与提交租约校验 | 按当前问题召回；队列不读写旧 Markdown，独立文件调用保持兼容 |
| 会话记录与压缩 | `internal/session/`、`internal/conversation/` | 原始消息、工具结果、journal、检查点、压缩内容 | 用于继续对话、恢复执行和控制上下文长度 |
| 当前提示词历史来源 | `prompt_memory_sources.go` / `Service.PromptSourceInventory` | 直接读取现有原记录，不新增一份记忆存储 | 沿真实组装入口列出当前可读取内容、注入位置和代码路径；按问题筛选的来源不宣称必然被选入 |
| 实际模型输入来源 | `prompt_memory_runtime.go` / `Service.SavePromptInput` | `memory_prompt_inputs` 中每次调用的实际来源摘录、发送状态和私有原源定位器 | 在最终序列化请求中匹配；原数据可独立读取和版本更正，历史输入摘录不随原源变化 |

会话恢复和上下文压缩属于运行状态管理，不等于已确认的长期事实。RAG 主要检索外部资料，也不能代替个人记忆。

2026-10-13 的 Go 升级将三条规则接入实际运行时：`explicit_user_memory.go` 按可信原话保存明确长期要求，稳定 key 保证重试不会覆盖人工更正或复活遗忘项；`task_reference_policy.go` 按真实执行回执/反馈筛选网页任务候选，保留原历史而排除普通问答和重复摘句；`source_recall_control.go` 用独立版本开关控制未来自动参考，在最终组装前检查并记录 `disabled_by_user`。管理页与运行时共用候选策略，停用后原内容仍可查看和重新启用。识别范围、证据、API 及非 Web 兼容限制见 [统一记忆服务合同](memory-service.md#原来源停止与恢复自动参考)。

### 2.1 分类、保存位置与如何回想

MySQL 与 SQLite 使用相同的旧记忆模型；`InitMemoryDB` 同时迁移旧表与新条目表，旧数据并没有因增加 `Service` 被替换。下面的文件位置均相对于当前工作区，`<Agent>`、`<会话>`、`<任务>` 是实际标识，不是固定文件名。

应用默认 SQLite 文件是 `.openkitty/openkitty.db`，可由 `OPENKITTY_SQLITE_PATH` 改变；MySQL 使用已配置的应用数据库中的同名表，不会另建一个“新记忆数据库”。图谱另外使用工作区内的 SQLite 文件，即使应用数据库使用 MySQL 也不改变这一点。自定义记忆目录或运行目录会改变旧 Markdown 日志的位置，应以配置及源码解析规则核对，不能仅凭默认位置判断数据丢失。

| 记忆类别 | 保存位置 | 普通 Agent 如何回想 |
| --- | --- | --- |
| 任务经历、工具/Skill 调用、结果与反馈 | 应用数据库 `memory_events`；问答消息另在 `chat_sessions` / `chat_messages` | 网页自动选择已核实会话的相关结果、既有经验、用户原话和反馈，每条单独筛选；`search_history` 可按需查成功任务。完整调用链不会全量注入 |
| 用户画像、偏好与约束 | 应用数据库 `user_profiles` | 网页不自动读完整画像，只参考核实后的偏好原话；界面可另显示严格匹配原话的约束。其他渠道保留旧画像适配；默认值不证明用户偏好 |
| 学习知识 | 应用数据库 `knowledges` | 网页只自动候选与已核实事件关联的学习知识；`knowledge` 可按需查找、列出或添加。存储或学习成功不等于本轮已经引用 |
| 工具/Skill 使用经验统计 | 应用数据库 `tool_skill_stats` | 网页不自动拼入统计表；其他渠道旧适配器仍可生成使用提示。`get_stats` 按需查次数、成功率、耗时；统计不是个人完整经历 |
| 已保存偏好、事实、决定与经验 | 应用数据库 `memory_entries` | `Service.Recall` 选择 active 且相关的条目，常驻偏好有独立限额；`agent_memory` 可按 key 回想或列出，候选不自动召回 |
| 会话工作状态与摘要 | `.openkitty/context/context.json`；应用数据库 `memory_summaries` | 当前会话的 SCM 项和相关数据库摘要参与统一召回；`session_context` 可按需读取，长期写入分流到 `memory_entries` |
| 图谱事实与原文证据 | `.openkitty/knowledge_graph.db` 的 `triples`、`entity_aliases`、`verbatim_memories`、`fact_evidence` | 网页只参考当前合法会话且用户原话仍能核实的事实；其他渠道保留旧可见性规则。旧关系、旧原文归档不是网页自动参考来源 |
| 上传文档与 RAG | 应用数据库 `rag_kbs` / `rag_chunks`，资料文件沿用上传目录 | `knowledge_query` / `knowledge_base` / `rag_search` 等已启用工具按需检索；显示父库元数据不等于自动读文档正文 |
| 工作区共同说明 | 根目录及受限子目录的 `AGENTS.md` | 动态系统提示中的项目说明加载器按工作区层级读取；`project_instructions` 可按需核对。它不走记忆 Recall，也不因全局页显示而扩大范围 |
| 学习经验文件与旧摘要 | `learn`：`.claude/projects/E--openkitty/memory/*.md`；旧摘要：`.openkitty/session-memory*.md` | `learn insights` 按需读取学习文件；当前统一召回不扫描这些 Markdown，摘要队列使用数据库摘要。`learn distill` 只返回提炼报告，不自动保存 |
| 原始执行记录与恢复状态 | `.openkitty/logs/transcripts/transcript_<任务>_<时间戳>.json`、同名 `.jsonl` 和 `.checkpoint.json`；旧可读日志通常在 `.openkitty/memories/<Agent>/MEMORY.md` 及 `logs/` | 用于检查执行证据、继续与恢复任务；不作为整份长期记忆自动注入 |

当前七个分类显示条目、会话状态、经过归属验证的有界来源，以及单独标记为未核实的工作区历史资料，不能视为所有表与文件的完整镜像。学习知识已经读取具备可验证事件来源的 `knowledges`：其 `SourceID` 必须关联同分区、Agent、用户、工作区与合法 Web 会话下的事件，归属未知的旧学习知识行不纳入个人学习来源。它与上传资料分开标为只读来源，不能用 RAG 管理入口代替。旧画像只有与合法原话严格匹配的约束可显示，完整画像、工具汇总和学习文件仍需各自的可信来源适配，不通过放宽过滤强行归属。

七类视图现在按用途分工：短期是当前会话工作状态和摘要；长期是 user 范围非偏好条目及已有经验，项目只显示项目条目及对应来源，用户偏好独立显示明确原话和有依据的约束。完整对话、任务结果与工具过程放在历史任务，避免短期与长期反复显示同一份原始日志。全局保留明确共享条目，另汇总根 AGENTS.md 和同工作区各助手的已保存条目；只读汇总不改原 Agent 归属或运行时共享范围。

知识分类还提供旧图谱关系与旧原文的独立分页。带会话来源的关系限经过验证的本助手会话；没有个人归属的旧资料标为“工作区旧知识，未核实”，保留真实时间与位置，不当作已确认事实。旧原文归档不读取带明确会话来源但尚未核验原话的记录。上传资料仅在当前工作区物理绑定的 SQLite 下显示默认本地租户的父库元数据；共享 MySQL、外置 SQLite 和其他租户仍走原资料管理权限。页内可见历史数量与资料目录的可信近期数量是不同口径，均不是个人全库总量。

知识主视图默认 `knowledge_source=curated`，集中显示合法学习知识、原话核实过的会话事实及 RAG 父库元数据。来源白名单为 curated/all/learning/rag/graph/quotes；all 中同一原图谱 ID 的核实事实替换旧归档，不重复计数，graph/quotes 需明确选择才分页查看历史关系或原文。图谱保留主体、关系、对象、来源、有效期、置信度及证据可用性，不能只按标题把它认作知识事实。学习知识标签来自原记录；显示的核实引用是实际匹配的 `evidence.verified_quote`，不从其他已存但未核实的引用推断。

用户偏好也可只读查看固定工作区 `.openkitty/context/context.json` 中没有会话 ID 的旧 preference 项，明确标为工作区历史偏好、归属未核实。非空会话来源、其他工作区、已知外部身份和内部执行项被排除，损坏文件保留并提示不可读；不是把旧文件全部搬成个人偏好。只有核对后显式另存才产生新的可编辑记忆，查看不构建 SCM、不改变 durable 或自动召回资格。

“页面能读取来源”不等于“这一轮已召回”。表中的自动回想描述运行路径具备的能力，每条实际选择仍取决于用户身份、会话、状态、关键词或语义相关性及预算。网页的新来源适配依据核实过的持久会话及事件归属；其他渠道的旧历史适配器还可能因缺少匹配 `user_name` 排除旧记录。新事件的用户名 fallback 不会迁移或回填旧数据。召回诊断记录宿主的选择，不证明模型采用或回答正确。

旧图谱的 `triples` / `verbatim_memories` 没有用户、Agent 或租户列：同工作区只能证明存储位置，不能证明当前用户认可这些内容。`conversation:session:<ID>` 可用于核对会话归属，原话仍需对照该会话的持久消息；旧 `conversation` 来源没有会话归属。图谱原句查询按实体或全文检索，不自带个人权限过滤，不能直接作为个人记忆列表。旧画像也只有租户与用户名，RAG 分块由所属知识库决定范围，均需各自的可信来源核对，不能凭同库或同名扩大归属。

旧 Agent JSON 与 durable SCM 已有一次性导入合同，但该导入不覆盖旧画像、`knowledges` 或 `learn` 文件。恢复展示应直接读取已有来源、保留真实时间与归属，不能通过移除身份过滤来聚合全部旧数据，也不能把所有历史记录自动复制成已确认条目。

### 2.2 实际查询与召回入口

- `search_history` 查询旧任务事件及解决方案；`get_stats` 查询工具与 Skill 统计。
- `agent_memory` 管理记忆条目，其中 `recall` 是按 key 查询的动作；`session_context` 管理会话状态并将 durable 写入分流至同一条目服务。
- `knowledge` 管理旧学习知识，`knowledge_query` 查询文档片段并可回退到旧知识表，`knowledge_base` 检索现有资料。
- `learn` 的分析和提炼返回报告；`memory` 动作保存 Markdown，`insights` 动作查询这些文件。文件保存不等于已进入自动召回。
- 普通模型回合由 `buildMemoryPrompt` 将该入口允许的来源交给 `Service.Recall`；网页用核实后的独立历史来源，其他渠道保留旧兼容适配，再统一做范围、相关性、预算与安全筛选。

当前没有已实现或注册的 `relook` 工具。Git 历史中曾有按 taskid/index 回看的注释设想，它不是可调用实现。工具注册与实际执行还受配置、记忆开关及隔离边界约束，不能据此认定所有 Agent 都能使用所有入口。

`reflection` / `rethink` 是 Agent 循环内的检查点与静态反思提示，不是独立持久记忆工具。重复失败产生的“避坑指南”保存为新的 `memory_events`；没有独立的 `traps` 工具或表。画像中的 `negative_patterns` 字段仍存在，但当前未找到将它用于提示词的运行链路。`workflow_learner` 保存的是可复用 recipe 与 Skill，属于技能管理，不是个人画像。

### 2.3 查看资料来源与实际数量

记忆窗口的 **查看资料来源** 使用只读 `GET /api/memory/catalog`，只接受当前已配置的 `agent`。它列出历史事件、画像、学习知识、工具/Skill 使用、已保存条目、摘要、会话状态、图谱、学习文件和 RAG 十种来源；展开 **保存在哪里** 可核对逻辑表名与工作区内的相对路径。不会暴露 MySQL 连接信息或工作区外的绝对文件位置。

数量只说明本次有界查询中经过归属核对的范围，不是数据库总量：历史与知识依赖最多 200 个已验证 Web 会话，工具调用数量来自其中最近 50 条事件，图谱数量也受证据核对和来源上限约束。未知数量显示为未知，接口值是 null；核对后没有记录才是 0。旧画像、归属未知的学习文件及 RAG 不被推算成个人数量，孤儿事件也不会按助手全库汇总归到当前用户名下。

“按问题自动回想”说明普通 Agent 有此读取路径；“通过工具按需查询”说明需要工具读取。两者都不证明本次已经采用；未开启或运行时尚未确认时，页面另给相应提示。目录只检查已有存储，不触发导入、迁移、记忆晋升、模型调用或实际召回；记录正文继续通过各自受限来源接口读取。完整字段与范围见 [资料来源目录合同](memory-service.md#资料来源目录)。

## 3. 普通 Agent 的实际读写流程

```text
用户请求与可信身份、工作区、会话
  → 恢复会话消息
  → 处理明确的长期偏好与纠正
  → Service 收集有效条目、当前会话工作状态与相关摘要
  → 网页加入核实过的独立历史来源与当前会话有证图谱事实
    （其他渠道保留旧历史/画像与图谱兼容适配）
  → 统一预算、去重、旧值原文屏蔽和提示注入扫描
  → Agent 推理与执行工具
  → 工具可按需读写手工记忆和持久上下文
  → 保存任务事件、消息和执行状态
  → 更新画像、提取会话上下文
  → 持久任务提取图谱事实与生成摘要，失败等待后续允许的回合重试
```

隔离内部任务、受限租户执行和记忆开关会跳过部分分支。当前 SCM 最多选 10 条非 durable 工作状态；网页历史候选来自最多 200 个已验证 Web 会话、最近 50 条合法事件，最终来源最多 120 条，仍需逐条相关性与预算筛选。其他渠道旧兼容适配的最近 3 条当前会话事件、1 条相似历史、2 条相关知识等上限不是网页新来源接口的合同。

实际入口是 `GatewayService.processTaskWithSession → LLMAgent.Generate → buildMemoryPrompt → Service.Recall`。网页 HTTP 宿主冻结私有来源范围，核对当前持久会话及其项目、工作区、用户和账号，单独提供偏好原话、反馈、任务结果、已有经验及关联学习知识；当前会话图谱还需核对用户证据。仅把 JSON 的 channel 填成 web 不会获得该范围；未封装的 Web 回合也不会退回旧混合画像/图谱。非网页调用保留 `GetMemoryContextForTenant` 与 `buildKnowledgeMemoryPrompt` 兼容片段。所有入口仍受相关性、去重、旧值撤回、预算及安全扫描约束。

按需查询发生在 Agent 执行过程中：模型调用已允许的 `search_history`、`agent_memory`、`session_context`、`knowledge`、`get_stats` 或 `learn`，工具返回的真实结果才进入该回合工具上下文。这与预先自动注入不同；`knowledge_query`、`knowledge_base` 的资料检索也走这条按需路径。

实际发送的记录入口在 `internal/app/prompt_memory_runtime.go`：Generate 建立可信 Web 私有收集器，读取 Recall、项目说明和持久历史消息时保存候选来源，`mac.go` / `gateway.go` 在最终请求授权、序列化之后及 HTTP 调用之前核对。历史来源还要求原消息身份、完整角色和正文保持一致；工具 `agent_memory` 与 `session_context` 的返回来源只有保留在后续实际 tool 消息里才计入。压缩、摘要或重写后失去精确映射的片段不冒充原文来源。每次尝试独立记录，成功 HTTP 响应只表示提交成功，不表示模型采纳或最终任务成功。

默认来源页采用只读 `GET /api/memory/prompt-sources?agent=...&session_id=...`。`personalPromptSources` 复用真实会话转换器、Web 独立历史参考和项目说明解析；统一服务另提供当前合法条目、SCM 与数据库摘要。`direct` 是组装代码直接加入，`relevant` 是需要相关性、预算和安全筛选，`on_demand` 是工具读取后才能进入，`none` 是当前入口不读取。该 GET 不运行模型、embedding 或 Recall，不创建 SCM、导入旧存储、写跟踪记录或新输入回执。源编辑通过服务器签发的短期 `view_id/source_id` 定位，不接受客户端表名、用户身份或文件路径。

这套记录目前覆盖普通 Web Agent 的主模型循环及其工具后续轮、对应流式和 Doubao 请求，不回填旧任务，不覆盖简单问答、直接媒体生成、AgentOS/渠道执行或内部辅助摘要调用。RAG 结果缺稳定原片段映射时不能据相似文本生成可写出处；没有来源记录也不等于没有其他上下文。完整合同及来源编辑边界见 [个人版记忆管理](memory-service.md#个人版记忆管理)。

旧历史工具与非网页兼容检索融合全文检索（SQLite FTS/BM25）、中文词项匹配和可选向量结果。词项降级扫描最近 200 条事件，向量检索主要扫描最近 50 条；向量缓存位于进程内，不是完整历史持久向量索引。网页新来源先核对归属并生成独立片段，不使用这套混合旧历史排名来扩大所有者范围。

统一 Recall 的长期条目基础候选最多 200 条，摘要基础候选最多最近 50 条；针对当前问题另做同范围关键词补查，最多各补查 200 条条目与 50 条摘要。关键词匹配由转义后的 SQL LIKE 与分词权重完成，不是旧事件的 BM25。默认总预算 2000、最多 8000 个估算 token，每片段最多 1200 字符；常见词过泛或超过上限时不能保证完整覆盖。active、source、priority 和 pinned 分别表示状态、出处、排序权重和常驻偏好，不是内容真实或本轮已采用的证明。

普通与共享数据库候选在 embedding 后重新核对命名空间、ID、版本、状态和 scope/session，防止检索期间已更正或遗忘的旧快照进入提示词。当前 SCM 在此核对之后加入；版本为 0 的合成工作状态不会冒充数据库条目。旧值撤回也对普通条目生效。诊断原因 `stale` / `version_changed` 只保留候选 ID 与旧版本，不保存原文；核对不是把数据库锁到模型调用结束。

配置 embedding 后，长期条目和数据库摘要另有持久语义缓存：按可信命名空间分页读取，可补回较早条目和改写问法。先收集已有缓存，再使用剩余时间回填缺失向量，每轮最多各 4 条，语义处理共用 3 秒预算；慢回填不会遮挡后面已缓存的结果。同一 Service 内的相同问题短暂复用查询向量，最多 1 分钟、32 条，按所有者和模型分开。更正、遗忘和模型变更会使旧文档缓存失效，后端不可用时保留关键词通道。此缓存不覆盖原始历史事件或旧 Markdown，真实模型的收益与误召回率仍需实测，详见[语义召回合同](memory-service.md#持久语义召回)。

### 3.1 简单问答与生成应用的区别

`task_type=qa` 在 Gateway 中直接调用 `simpleChat`，消息仅包含固定问答系统说明、当前会话中已清理的 user/assistant 历史和当前输入。它不创建 Agent、不调用 `buildMemoryPrompt` / `Service.Recall`，也不能使用上述记忆工具。保存问答消息或在页面查看回答摘录，不代表这一轮简单问答使用了 Agent 长期记忆。

图片、音乐等直接生成请求同样不进入 `LLMAgent.Generate`。生成记录与会话快照能用于查看和继续任务，但不能据此声称执行过记忆工具、完成复盘或已经建立长期偏好。

## 4. AgentOS 多用户隔离

同一个 Agent 可以服务不同用户，但个人记忆按认证后的身份隔离。三个概念需要分开：

| 身份 | 含义 |
| --- | --- |
| `tenant_id` | 所属组织或租户 |
| actor / 服务凭证 | 调用 API 的服务或主体 |
| `subject_id` / `user_id` | 当前任务的数据归属人 |

当前隔离链路包括：

1. **数据库分区**：从认证后的 `tenant_id + subject_id` 派生个人分区，用于历史、画像和知识记录的读写过滤。为兼容现有表结构，个人分区当前写入已有 `tenant_id` 列。
2. **个人工作区**：AgentOS 将任务绑定到用户工作区，并在该工作区创建任务 Agent。手工记忆、持久上下文和摘要文件因此分别落在不同用户目录。
3. **会话隔离**：外部 `session_id` 按租户和用户转换为内部 ID，不同用户传入同一会话名称也不会直接复用同一内部会话。
4. **全局图谱限制**：受限租户执行不读取当前全局知识图谱，也不通过该全局图谱派生事实。这是保护边界，尚不等于拥有完整的个人图谱服务。

业务后端代表自然人调用时，应配置 `users:act_as` 和 `require_user_id: true`，在提交、查询、SSE、取消等请求中携带 `X-OpenKitty-User-ID`。请求体若包含 `user_id`，必须与 Header 一致。用户身份应由受信业务后端根据登录信息确定，服务凭证保留在后端。详见 [AgentOS API 接入说明](../agent-os-api.md)。

上述机制针对认证后的租户与个人执行链路，不能把本地或控制面兼容调用中随意传入的 `user_id` 当作同等隔离保证。

## 5. 当前已经实现的可靠性能力

- 手工记忆支持明确作用范围、版本更正和删除标记，阻止已删除记录被旧数据合并恢复。
- 文件采用原子保存，并处理损坏文件、保存失败和内存回滚。
- 新增自动图谱事实要求匹配用户原文证据，事实与证据一起保存。
- 自动提取的部分上下文限制在原会话，减少一次性要求进入长期记忆。
- 记忆开关约束自动召回、自动提取与相关工具；历史查询、知识管理和会话恢复仍有独立入口。
- 摘要使用独立的会话状态，失败或取消后不推进成功写入进度。

原文证据只证明引用存在，并不保证模型解释正确。新规则也不会自动把旧记录变成已验证事实。

## 6. 当前主要问题

| 问题 | 当前表现 | 对用户的影响 |
| --- | --- | --- |
| 历史覆盖有限 | 新长期条目和摘要已接通；旧摘要未批量索引 | 升级前的旧摘要仍需按文件查询 |
| 部分来源仍独立 | 手工与 durable 上下文已统一，画像与图谱仍独立 | 语义冲突与完整派生血缘还需完善 |
| 多来源范围仍有区别 | 原记忆仍绑定 Agent，新增 global 仅同个人工作区全部助手共享；画像与图谱仍独立 | 不能将工作区共享解释成跨项目、跨目录或团队公共记忆 |
| 遗忘范围有限 | 数据库版本和删除标记生效；补充片段按旧值原文哈希屏蔽 | 不能识别全部语义改写，也不物理清除原始证据 |
| 长期召回覆盖有限 | 长期条目与数据库摘要已有持久语义缓存，按回合有界回填；原始历史和旧文件未全量索引 | 冷启动、很大的命名空间和实际模型的语义效果仍需评测 |
| 自动提取可靠性不一致 | 画像存在关键词推断；图谱依赖模型解释 | 推断可能被误当作确认事实 |
| 后台恢复依赖后续回合 | 已有持久队列、幂等、超时与租约；没有常驻轮询器 | 用户未再发起允许的回合时不会自动处理积压 |
| 管理与评测仍有范围限制 | 长期条目已有统一列表、编辑窗口、来源和召回记录；跨存储遗忘和真实模型评测仍不完整 | 可以核对长期记忆及选择原因，但不能据此证明全部历史已删除或模型实际采用 |

手工记忆的 `user` 目前表示当前工作区与 Agent 内的持久偏好，不是跨工作区、跨 Agent 的个人总画像；`project` 也不自动代表团队共享记忆。AgentOS 的个人工作区隔离需要继续保留，不能通过扩大文件读取范围来实现共享。

新增 `global` 使用独立的所有者/工作区命名空间，只有明确的手工管理可新增、更正、常驻或遗忘，不自动导入和晋升旧内容。当前助手将自己的记忆和共享条目在一次 Recall 中选择，同名有效相关条目按 session > project > user > global 选择，并共用 token 与语义时间预算。关闭记忆或内部隔离执行时也不会读取共享记忆。短期分类可新增和版本更正真实 Web 会话笔记；SCM 与自动摘要只读显示真实时间、来源，不能直接编辑。管理 API 继续是本机单用户控制面，平台登录不授予跨用户记忆权限。

管理页还读取已验证 Web 会话的既有 MemoryEvent、任务经验、工具名与结果状态、明确反馈和偏好原话，以及关联这些事件的学习知识，作为只读来源；有证据的会话图谱事实需重新对照原用户消息。普通问答没有任务事件时展示真实回答摘录，不造工具记录或自动总结。已保存 Entry 与历史来源分别计数，默认画像和一次性要求不伪装成长期偏好。来源不会因为页面打开自动写入、晋升或跨工作区导入；用户核对后可以另存为现有可编辑 Entry。详见 [统一记忆服务的来源合同](memory-service.md#已保存条目与真实任务来源)。

## 7. 个人版的整理方向

统一入口、数据库长期集合、有界召回和持久任务已实现。进一步完善证据血缘、管理界面与检索覆盖，继续维持简单、可运行的 Go 与本地存储方案：

| 层次 | 内容 | 读取方式 |
| --- | --- | --- |
| 核心记忆 | 用户明确的长期偏好、约束和关键项目状态 | 每轮有界注入 |
| 可检索记忆 | 事实、决定和任务经验 | 按当前问题检索 |
| 原始记录 | 聊天、工具结果与摘要 | 查证和恢复时读取 |

当前已验证统一集合的跨会话读取、更正与删除保护；后续重点是跨来源语义一致性、管理界面和更完整的检索评测。
