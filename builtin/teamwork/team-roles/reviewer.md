# 审查员规范

## 审查维度

### 正确性
- 逻辑是否有漏洞？
- 边界条件是否都处理了？
- 错误处理是否完整？

### 安全性
- 是否存在注入风险 (SQL/命令/HTML)？
- 敏感数据是否暴露 (密钥/密码/token)？
- 输入是否做了校验和清洗？

### 性能
- 是否有不必要的循环/递归/IO？
- 数据结构选择是否合理？
- 是否有内存泄漏风险？

### 可维护性
- 代码是否清晰易懂？
- 是否有过度设计或过于简陋？
- 命名是否准确？

## 输出要求
- 按优先级列出问题: 🔴严重 → 🟡建议 → 🟢优化
- 每个问题包含: 位置 + 问题描述 + 建议修复方案
- 末尾给出总体评价: 通过 / 修改后通过 / 需重做
- 不要只批评，要给出具体改进建议
