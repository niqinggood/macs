# 报价披露与方案保护

目标不是把报价写得模糊，而是让客户能判断“买什么、多少钱、何时交付、怎么验收”，同时不免费交付一份可直接换供应商实施的蓝图。

## 三层文件必须分开

| 层级 | 受众 | 应包含 | 不应包含 |
|---|---|---|---|
| 内部测算版 | 售前、交付、财务、审批人 | 完整 WBS、O/M/P、角色人日与价卡、成本/毛利、技术判断、风险、底价、折扣权限 | 不作为外发附件 |
| 客户商务版 | 客户决策人、采购、招标方 | 业务目标、模块级成果、验收口径、阶段总价、工期、客户责任、排除项、付款、变更 | 逐任务人日、角色单价、成本/毛利、API 路径、数据表/字段、算法/Prompt、技术选型清单、部署拓扑 |
| 付费方案版 | 已签方案阶段或整体项目的客户 | 需求基线、原型、架构基线、接口契约、数据模型、容量/安全方案、实施计划及约定知识产权 | 未付款前不交付；超出合同的研究成果不自动开放 |

不要在同一个 Excel 中用“隐藏列/隐藏 Sheet”区分内外版。隐藏内容仍可能被取消隐藏、复制或从文件 XML 中读出。客户版应从安全模板独立生成，并使用不同文件名和目录。

## 免费售前的披露上限

免费阶段可以给：

- 对业务目标和问题的理解；
- 端/平台/业务域级别的范围，例如“小程序端、H5、运营后台、公共服务端、算法服务”；
- 3-7 个模块或阶段，每项说明业务成果和客户可观察的验收结果；
- 总价或预算区间、总工期、付款建议、关键前提、第三方费用和排除项；
- 能证明团队理解力的少量关键风险与应对原则。

免费阶段不要给：

- API 方法与路径、接口字段、错误码、SDK 结构；
- 数据库表、字段、ER 图、缓存 Key、消息 Topic；
- 服务拆分、组件/中间件清单、部署拓扑、容量公式、机器规格；
- 算法流程、模型选型、Prompt、权重、训练/路由细节、评测集设计；
- 可直接导入项目管理工具的任务树、逐角色人日、排期依赖；
- 内部成本、毛利、红线价、折扣授权和供应商底价。

客户要求“证明能做”时，优先展示脱敏案例、演示、团队能力和验收方法，不交付当前项目的完整实现蓝图。

## 把详细方案产品化

当需求尚未冻结，或客户要求原型、架构、接口、数据模型、压测/算法路线后再决定是否开发时，先销售“方案定义/技术尽调”阶段：

| 项目 | 写法 |
|---|---|
| 目标 | 冻结实施所需的需求、边界、验收和关键技术决策 |
| 周期 | 给明确窗口；客户资料、访谈和评审等待单列 |
| 费用 | 固定阶段价或预算上限；不要写成“免费售前支持” |
| 交付物 | 需求基线、原型、架构基线、验收矩阵、实施预算；深度以合同为准 |
| 决策门 | 继续实施、调整范围或停止；每种结果的权利义务明确 |
| 抵扣 | 可约定在指定期限内签实施合同时抵扣全部或部分方案费，但不是默认免费 |
| 知识产权 | 通用方法、框架和既有资产归属不因交付项目文档而自动转让 |

若客户拒绝支付方案阶段，只提供商务版所需信息，不继续展开可执行细节。

## 客户版的正确颗粒度

每项范围使用四个字段：

| 字段 | 说明 |
|---|---|
| 能力域 | 客户能理解的模块或阶段，不使用内部任务编号 |
| 业务成果 | 上线后能完成的业务闭环或运营能力 |
| 可验收结果 | 双方能观察、演示或测量的通过条件 |
| 边界/依赖 | 客户输入、第三方依赖、选项和不包含内容 |

例：客户版写“支付与订单闭环：完成下单、支付结果确认、订单查询和异常提示；使用双方测试账号完成主流程验收”。不要写具体回调 URL、状态表、幂等键、消息队列或数据库字段。

并发与算法项目仍要可验收，但只披露“指标 + 测试边界 + 决策门”：

- 并发：说明双方待确认的业务流量情景、响应指标和压测报告，不给容量公式、节点数和拓扑；
- 算法：说明数据责任、基线、指标、切片和 Go/No-Go，不给模型结构、超参、Prompt 或训练流程；
- 框架/平台：说明可扩展能力和兼容性验收，不给插件机制、核心抽象、目录和源码设计。

## 价格、工期与版本一致性

同一客户包只能存在一个权威商务口径。发送前核对：

- 总价是含税还是未税，税率和开票主体是否明确；
- 优惠价是否能由指导价减优惠额复算，优惠是否有有效期；
- 阶段金额和付款节点之和等于总价；
- “60天、12周、3个月”等口径不得混用；必要时明确自然日/工作日和停表条件；
- PPT、报价书、邮件正文和附件中的版本、日期、范围、金额、工期一致；
- 周期性/按量费用不混入一次性项目总价。

## 文件与发送控制

- 客户版文件名带报价编号、版本和 `客户版`；内部版带 `内部-禁止外发`。
- 客户版放独立目录；不要从含 `bak`、`任务拆解`、`成本`、`架构详设`、`标准规范` 的目录整包发送。
- 必要时添加客户名、报价编号和用途水印；水印只用于追踪，不能替代内容删减。
- 外发前运行 `scripts/review_client_quote.py <文件> --strict`。阻断项必须清零；警告必须逐条确认保留理由。
- 发送记录保存版本、收件人、附件哈希或最终文件清单，避免后续争议。

## 对外沟通句式

客户索要更细方案时，可以直接说明：

> 当前商务报价已覆盖范围、成果、验收、周期和价格，足以进行采购判断。接口、数据模型、详细架构与实施任务书属于方案定义阶段的付费交付物；启动该阶段后，我们会在双方确认的保密和知识产权边界内完整交付，并可按合同约定抵扣后续实施款。

保持专业、简短，不用“防白嫖”等内部措辞出现在客户文件中。
