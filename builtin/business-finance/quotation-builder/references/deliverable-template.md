# 报价交付模板

正式合同、税务和法律条款应由有权限的人员复核。本模板重点保证客户能做采购决策，同时避免把内部测算或可执行技术方案误发出去。

## 先选受众，不做混合版

- `内部-禁止外发`：完整 WBS、三点估算、角色人日/价卡、成本、毛利、技术路线、风险和谈判底线。
- `客户版`：范围、成果、验收、阶段总价、工期、客户责任、排除项、付款和变更。
- `付费方案版`：仅在方案阶段或整体项目已签约后，交付原型、架构、接口、数据模型、容量/算法方案和实施计划。

客户版必须从下面的安全结构独立生成。不要复制内部 Excel 后隐藏列，也不要把内部版作为附件一起发送。详细规则见 [disclosure-policy.md](disclosure-policy.md)。

## 客户商务版

### 一页决策摘要

```markdown
# <项目名称> 商务报价书（客户版）

- 报价编号：<编号>
- 客户 / 供应方：<名称>
- 版本与日期：<版本> / <日期>
- 报价级别：ROM / 预算级 / 正式报价
- 报价口径：<币种>；含税/未税；税率及开票主体 <已确认或待确认>
- 有效期：<日期>
- 交付模式：固定总价 / 迭代预算上限 / 分阶段门控

## 商务结论

- 项目总价或预算区间：<金额>
- 工期口径：<自然日/工作日/周；起算与停表条件>
- 启动条件：<最关键的 3-5 项>
- 周期性与按量费用：<另列，不混入一次性总价>
- 报价成立条件：<关键假设>
```

ROM 阶段缺少可靠价卡、税率或范围时，保留区间和待确认字段，不制造一个“看起来完整”的固定总价。

### 范围、成果与验收

客户版控制在 3-10 个能力域或阶段，不下钻到页面、接口、表、类、算法步骤或逐任务工时。

```markdown
| 能力域/阶段 | 业务成果 | 可验收结果 | 客户输入与边界 |
|---|---|---|---|
| 小程序/H5 用户端 | <可完成的业务闭环> | <演示、测试或数据结果> | <账号、内容、审核等> |
| 运营管理后台 | <可管理的对象和流程> | <角色完成主流程> | <组织权限、数据等> |
| 公共服务与集成 | <对接后的业务结果> | <双方测试环境联调通过> | <第三方账号/API 审批> |
| 性能/算法专项 | <经验证的能力> | <指标、样例集、测试边界> | <数据/流量条件与决策门> |
```

正确颗粒度是“客户买到的能力 + 如何验收”。不要出现 API 方法/路径、字段、数据库表、技术栈清单、部署拓扑、模型/Prompt/权重或内部任务编号。

### 付费方案定义阶段

需求未冻结或客户要求详细方案后再决定是否开发时，增加这一节：

```markdown
## 方案定义阶段

- 阶段价：<金额>
- 周期：<窗口与客户等待条件>
- 交付：需求基线、原型、架构基线、验收矩阵、实施预算；具体深度以阶段合同为准
- 决策门：继续实施 / 调整范围 / 停止
- 抵扣安排：<指定期限内签实施合同后抵扣全部/部分；未约定则不抵扣>
- 权利边界：通用方法、框架与既有资产不因项目文档交付而自动转让

说明：详细接口、数据模型、技术选型、容量/算法路线和实施任务书属于本付费阶段交付物，不在免费售前材料中提供。
```

### 里程碑、费用与付款

```markdown
| 里程碑 | 客户可见成果 | 验收门 | 阶段金额 | 付款节点 |
|---|---|---|---:|---:|
| 启动/方案定义 | ... | ... | ... | ... |
| 核心能力可验收 | ... | ... | ... | ... |
| 联调/UAT | ... | ... | ... | ... |
| 上线/移交 | ... | ... | ... | ... |
```

检查阶段金额、付款金额和总价完全一致。不要在客户版展示角色人数、人日、日单价、内部成本、管理费率、准备金、毛利或折扣授权。若要体现优惠，只展示“指导价、优惠额、客户成交价、有效期”，内部毛利检查另存。

### 并发、容量与算法验收

客户版只写可观察结果和边界：

```markdown
| 专项 | 目标/情景 | 测试边界 | 验收输出 | 未确认影响 |
|---|---|---|---|---|
| 性能与容量 | <关键业务流量/时延目标> | <环境、数据、时长、第三方是否计入> | 压测报告与双方确认结果 | ... |
| 可用性/恢复 | <SLO、RTO/RPO> | <计划维护、外部故障边界> | 演练记录 | ... |
| 算法/AI | <基线、指标、数据切片> | <数据权利、样本量、人工复核> | 评测报告与 Go/No-Go | ... |
```

目标尚未确认时，报价“容量发现/算法 Spike 阶段”，不要保证空泛的“百万并发”或未经验证的模型效果。节点数、拓扑、容量公式、模型结构、超参和 Prompt 留在付费方案版或内部版。

### 费用汇总

```markdown
| 费用类别 | 未税金额 | 税 | 含税金额 | 计费方式 | 是否计入本次总价 |
|---|---:|---:|---:|---|---|
| 技术交付 | ... | ... | ... | 一次性 | 是 |
| 方案定义 | ... | ... | ... | 一次性/可抵扣 | ... |
| 运维支持 | ... | ... | ... | 月/年 | 否/是 |
| 云资源/API/短信/模型调用 | ... | ... | ... | 按量 | 否 |
```

第三方、云、短信、地图、模型 API、GPU、证书和许可证按一次性、周期性、按量分列。对客户说明计费责任和价格变动机制，不披露供应商底价或平台毛利。

### 商务边界

至少说明：

- 付款节点与对应可验收成果；
- 币种、税、发票、汇率和第三方费用；
- 客户提供账号、数据、内容、接口、测试人员和确认反馈的责任；
- 源码、知识产权、开源/商业许可证和交付介质；
- 质保覆盖范围内缺陷还是功能增强，起止条件和服务窗口；
- 数据安全、隐私、访问权限和删除/返还；
- 报价有效期、开始条件、暂停/延期/取消与重新排期；
- 方案定义成果的使用权及通用方法/既有资产边界。

付款比例不要套固定模板，应与现金流、里程碑价值和交付风险匹配。

### 假设、排除项与变更控制

```markdown
## 已确认事实
- ...

## 报价假设
- A-01：...；若不成立，影响模块/金额/工期为 ...

## 待确认项
- Q-01：...；最晚确认时间 ...

## 排除项
- ...

## 变更触发
- 新增端、角色、业务流程、第三方系统或数据源；
- 验收指标、容量、可用性、安全或合规等级变化；
- 客户数据/接口与已提供样本显著不一致；
- 外部平台政策、收费、审核或交付窗口变化；
- 已验收范围返工或时间窗口压缩。

## 变更流程
提出变更 → 评估影响 → 双方确认 → 更新商务与验收基线 → 实施。
```

## 内部审批版

内部版应保留而客户版不得出现：

- 完整 WBS：ID、交付物、角色、O/M/P、预算人日、内部日成本/售卖价和状态；
- 多端复用矩阵、公共工程、依赖 DAG、关键路径和人员排期；
- 并发容量推导、节点/规格、技术栈、部署拓扑和压测优化计划；
- 算法路线、模型/Prompt、评测设计、计算预算、MLOps 与持续运营工作；
- 价卡来源、P80/P95、间接成本、准备金、毛利、折扣后实际毛利；
- 外采底价、汇率、税、审批、红线价格、可让渡项和谈判策略；
- 与历史项目的偏差解释和风险登记册。

内部计算器输出属于本层，不得直接转发。

## 发送前检查

- 总价、税、优惠、阶段金额、付款金额能互相复算；
- 工期统一为自然日/工作日/周，并写清起算、等待与停表条件；
- PPT、报价书、邮件正文和附件的版本、范围、金额、工期一致；
- 一次性、周期性和按量费用分列；
- 客户版验收清楚，但没有可直接实施的 API、表结构、算法或拓扑；
- 内部成本、角色价卡、毛利、红线和谈判底线未外发；
- 客户版与内部版不在同一工作簿、压缩包或共享目录；
- `python scripts/review_client_quote.py <客户文件> --strict` 无阻断项，警告已逐条确认。
