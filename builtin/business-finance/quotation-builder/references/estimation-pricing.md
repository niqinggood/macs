# 估算、排期与商务计算

本参考定义数字口径。先使用用户或组织的历史数据和价卡；没有证据时输出显式情景，而不是伪造“行业标准人天”。

## 证据层级

估算项旁标明最强证据：

1. 同团队、同技术栈、相似范围的实际完工数据；
2. 当前项目的 Spike、原型、性能基准或代码审计；
3. 负责执行人员的逐项三点估算；
4. 可比项目/标准化功能规模与已校准生产率；
5. 公开市场基准；
6. 未验证假设。

证据越靠后，区间应越宽，报价成熟度越低。公开市场报价只能作外部视角，不能替代本团队生产率和成本结构。

## 方法选择

| 方法 | 适用条件 | 不适用/注意 |
|---|---|---|
| WBS 自下而上 | 范围能拆到交付物，默认首选 | 容易漏公共工作和相关风险，需交叉复核 |
| 三点估算 / PERT | 单项存在可描述的不确定性 | O/M/P 必须同口径；不是结果保证 |
| 类比估算 | 有相似项目实际数据 | 需解释规模、复杂度、复用和团队差异 |
| COSMIC/功能规模 | 需求可表达为功能过程，组织有生产率基线 | 功能规模不自动覆盖全部 NFR、迁移和治理成本 |
| COCOMO II | 有可靠规模、成本驱动和组织校准 | 不从想法臆测 KLOC；不用未经校准的默认值形成正式报价 |
| Time & Materials | 范围持续变化、研究或遗留系统未知 | 要设迭代预算、上限、透明台账和停止条件 |
| 固定总价 | 范围、验收、依赖和变更机制已冻结 | 未知风险会转为高准备金或争议，不适合开放式研发 |

至少用一种主方法和一种独立校验视角。两者差异大时解释原因并返回范围澄清，不要机械平均。

## 三点估算

对单项任务：

- `E = (O + 4M + P) / 6`
- `σ = (P - O) / 6`

其中 O、M、P 都是完成相同交付物和验收条件所需的人日。O 不是“零缺陷且不测试”，P 也不是把所有灾难叠在一起。

若为了预算近似而假设任务误差独立：

- `总 E = ΣEᵢ`
- `总方差 = Σσᵢ²`
- `总 σ = √Σσᵢ²`
- 正态近似下：`P80 ≈ E + 0.8416σ`，`P95 ≈ E + 1.6449σ`

这些是近似预算分位，不是严格置信区间。软件任务常共享需求、架构、人员和外部依赖，存在相关性；忽略相关性通常会把区间算得过窄。重大项目应建相关风险或做蒙特卡洛，而不是只展示精确小数。

## 风险处理与防重复

建立风险登记册：

| 风险 | 影响 WBS | 概率/触发 | 成本/工期影响 | 缓解动作 | 是否已在 O/M/P 中 |
|---|---|---|---|---|---|

可识别风险优先放到对应 WBS 或单独风险驱动中；一般估算误差可由三点区间表达。若同一风险已经放大 P 值，不再以相同理由叠加准备金。准备金与利润分开：准备金覆盖交付不确定性，利润是商业回报。

## 人日与日历工期

先画依赖 DAG 和关键路径，再排人员。日历工期至少考虑：

- 任务依赖与可并行工作流；
- 每个角色的可用人数、投入比例、假期和上下文切换；
- 评审、UAT、外部接口、数据/账号和平台审核等待；
- 集成、稳定、回归、发布窗口和缺陷修复；
- 沟通、交接和新增人员爬坡。

`总人日 ÷ 总人数` 只能是理论下限，不能直接作为承诺工期。分别输出工作量、关键路径工期和建议团队结构。

## 并发与容量的可计算口径

只有用户行为数据足够时才推导：

- `峰值 QPS ≈ 峰值活跃用户 × 每用户每分钟操作数 ÷ 60 × 突发系数`
- `带宽 ≈ QPS × 平均响应字节 × 协议/重试系数`
- `日增数据 ≈ 日请求或事件数 × 单条持久化字节 × 副本/索引系数`

对不同接口分别估算，再按流量混合汇总。登录、搜索、下单、上传、推理和批处理的资源特征不同，不能只给一个总 QPS。容量报价要包含验证环境、脚本、数据、监控、压测执行、瓶颈优化和复测；硬件/云费用另列。

## 成本到价格

先说明采用内部成本价卡还是对外售卖价卡。本技能的计算器采用**内部交付成本价卡**（每角色每人日完全成本）并按以下顺序计算：

1. `角色直接成本 = Σ(所选置信水平的人日 × 角色日成本)`
2. `间接成本 = 角色直接成本 × 间接成本率`
3. `成本基数 = 角色直接成本 + 间接成本 + 一次性外部成本`
4. `风险准备金 = 成本基数 × 准备金率`
5. `交付总成本 = 成本基数 + 风险准备金`
6. 目标毛利率法：`折扣前未税价 = 交付总成本 / (1 - 目标毛利率)`
7. `折扣后未税价 = 折扣前未税价 × (1 - 折扣率)`
8. 按约定粒度取整，再计算税额和含税总价。

若组织使用成本加成法，改用 `价格 = 成本 × (1 + 加成率)`，不要同时套目标毛利率。若输入是对外售卖人日单价，则应按售卖价汇总，并另做内部毛利检查，不要再次加毛利。

### 毛利与加成

- `毛利率 = (未税收入 - 交付成本) / 未税收入`
- `加成率 = (未税收入 - 交付成本) / 交付成本`

折扣会降低实际毛利率。输出目标毛利率和折扣后的实际毛利率，避免“先加利润再随意打折”。

### 税和币种

- 明确含税/未税、税种/税率来源和开票主体；税率缺失时不猜。
- 外币费用标原币、汇率来源/日期和汇率风险承担方。
- 第三方、云、短信、地图、模型 API、GPU、证书和许可证分为一次性、周期性、按量；不要全部塞入开发费。

## 计算器输入

`scripts/calculate_quote.py` 接受一个 UTF-8 JSON 文件：

| 字段 | 必填 | 说明 |
|---|---|---|
| `project.name` | 是 | 项目名 |
| `project.currency` | 是 | 如 `CNY`、`USD` |
| `project.pricing_confidence` | 是 | `expected`、`p80` 或 `p95` |
| `rate_card` | 是 | `{角色: 每人日内部成本}`，值必须大于 0 |
| `items` | 是 | WBS 数组；含 `id/workstream/deliverable/role/optimistic/most_likely/pessimistic` |
| `items[].rate_override` | 否 | 此行专用内部日成本；存在时覆盖角色价卡 |
| `one_time_costs` | 否 | `{name, amount}`；计入本项目交付成本 |
| `recurring_costs` | 否 | `{name, amount, period}`；只列示，不计入一次性总价 |
| `commercial.overhead_rate` | 是 | 间接成本率，0 到 1 之间 |
| `commercial.contingency_rate` | 是 | 风险准备金率，0 到 1 之间 |
| `commercial.target_margin` | 是 | 目标毛利率，0 到 1 之间且不能等于 1 |
| `commercial.discount_rate` | 是 | 折扣率，0 到 1 之间 |
| `commercial.tax_rate` | 是 | 税率，0 到 1 之间 |
| `commercial.round_to` | 是 | 未税价取整粒度；`0` 表示只保留分 |
| `commercial.rounding` | 否 | `up`（默认）或 `nearest` |

运行 `python scripts/calculate_quote.py --example` 查看完整示例。示例数字仅用于验证格式，不能当行业价卡。

### 计算器输出解释

- `expected`、`p80`、`p95` 是工作量/直接成本的近似情景；
- `selected_*` 是实际用于定价的置信水平；
- `quote.pre_tax_after_discount` 是取整后的未税报价；
- `quote.actual_margin_after_discount` 用折扣后未税收入计算；
- `recurring_costs` 仅列示，必须在报价中说明周期和用量条件。

计算器假设 WBS 行的不确定性相互独立，只适合一般预算复核。若重大共享风险、强相关任务或高风险投标会改变决策，使用风险驱动蒙特卡洛或公司批准的估算模型。

## 市场价格研究

用户明确要求“市场行情/外包价/本地人天”时：

1. 先确认地区、币种、团队类型、资历、交付责任、时间点和含税口径；
2. 搜索并打开当前来源，优先官方采购价、公开中标/框架协议、可靠薪酬/承包商数据；
3. 至少给来源日期、地区、角色定义和样本局限；
4. 把市场基准作为情景，不冒充本公司的成本或承诺报价；
5. 用户禁止联网时只输出待填价卡和公式，不引用记忆中的具体市场价格。

## 实际值回灌

项目结束后保存原始估算、变更、实际工时/成本和偏差原因。下一次类比使用“冻结范围后的实际值”，不要用销售目标或未剔除范围变更的最终总工时校准。
