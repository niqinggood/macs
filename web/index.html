TODO 是什么

TODO 是手动设置的定时任务系统，让 AI 在指定时间自动执行你设定的工作。


为什么要用

适合周期性重复工作：每天早上8点汇总财经新闻、每周五生成周报、每月1号做数据报表。设定一次，自动执行。


怎么用

1. 在 创建 页填写任务描述、选择执行的 Agent

2. 选择执行类型：一次性（指定时间）/ 每天 / 每小时 / 自定义Cron

3. 到时间后 AI 自动执行，结果可在 列表 页查看


注意：对话中让 AI"明天8点提醒我"不会自动创建 TODO，需要手动在这里设置。AI 只能设置天级别的定时任务。

关于 macs

Multi-Agent Collaboration System

macs（麦卡斯）

中文名：麦卡斯 英文全称：Multi-Agent Collaboration System 内部代号（小名）：openkitty
v1.1.20

面向个人与团队的本地优先多智能体协作系统，将 Agent、工具、技能、工作流、知识和可靠任务执行整合在一个可部署平台中。

配置模型

先在输入框下方点“选择模型”。平台模型登录后即可选择，价格显示在模型旁；自定义模型使用自己的服务地址、模型名和 API Key。

已有可用模型时直接使用。助手没有单独指定模型，就跟随当前文字模型；生图、音乐、视频使用各自的生成模型。

开始对话

  1. 选择模型和对话方式：简单问答直接回答；Agent 模式会规划步骤、使用工具完成任务。
  2. 写清楚想得到什么，也可以用“提示词模板”填入模板，需要时添加图片或文件。
  3. 检查后发送。执行进度会显示在对话中，生成的文件可在“交付物”中打开。

个人助手

助手就是一位有固定职责的 AI，例如写作助理、研究助手或电商顾问。在“我的助手”中使用已有助手，也可以新增自己的助手，填写名称、职责和操作要求。

模型留空时跟随当前文字模型；单独选择模型后，这个助手固定使用它。skill 提供知识、技能和专家 SOP（操作手册）；工作流用于需要严格按步骤执行的任务。

本机启动、移动办公和脚本检查
Windows：双击启动，在页面里完成设置
  1. 解压程序，双击 openkitty.exe。

    首次启动会准备配置并打开网页。看到运行窗口后保留它；电脑和程序保持运行，助手才能接收任务。

  2. 在输入框下方选择模型。

    平台模型：登录 SICurrent 后选择，按页面价格扣费。自定义模型：打开 AI 服务设置，填写服务商给你的 API 地址、模型名和 API Key，然后保存。

  3. 先发一句普通问题，确认能回答。

    保存后的模型配置会保留。下次双击启动即可；日常聊天、Agent 任务和连接应用，都从页面中操作。

连接应用，就是移动办公

连接微信、QQ 等应用后，可以在手机上发任务、收结果。macs 所在电脑需要保持运行；接入步骤在各应用的接入指南里。

双击后没有打开网页，怎么办？

在运行窗口找到 Web 地址，复制到浏览器。启用了“启动时不打开网页”时需要手动打开；启动报错时先看窗口中的错误。默认端口是 8080，被占用时可能顺延，以实际显示的地址为准。

配置按当前工作目录、用户配置目录的顺序查找；桌面快捷方式的工作目录可能与原程序不同。运行指定配置或保留同一个工作目录时，使用下面的终端命令。PowerShell 临时设置的密钥不会自动传给另一次双击启动。

可选：让自己的脚本调用本机 macs

本机试用可以复用现有助手和 Web 端口。先检查服务，再下载 Python 脚本；没有独立端口时，服务地址就是当前网页地址去掉 /web/。

下载 Python 检查脚本

python agentos_check.py --local --url http://127.0.0.1:8080

本机检查只查看服务和助手列表，不提交任务。仅在本机未启用认证时可省略服务凭证；已启用认证或独立端口时，按下面的 AgentOS 接入步骤配置。

AgentOS 后台调用需要可用的自定义模型密钥或平台访问密钥；网页登录状态不会传给后台任务。本地 Ollama 也需要先安装并启动对应模型。服务检查通过不等于模型已经能回答。

主要功能

从一次对话到可恢复的长期业务流程，MACS 使用同一套 Agent 运行时、权限边界和任务协议完成执行。

◎
Agent 智能执行
通过“模型—工具—再推理”循环完成规划、执行、校验与结果交付。
◇
多 Agent 协作
支持角色分工、任务委派，以及串行、并行和混合协作。
↻
AgentOS 可靠任务
提供异步任务、幂等、队列、租约、事件流和中断恢复能力。
⇄
工作流
以输入输出契约、检查点、审批、返工和恢复控制多步骤流程。
✦
Skills 与工具
按需发现和激活能力，并通过权限与中间件约束真实动作。
▣
AI Employee
将业务身份、消息路由、工作时间和工作流绑定为数字员工。
⌁
知识与记忆
结合 RAG、会话持久化和长期记忆，让执行拥有可追溯上下文。

团队与工作流

项目专家团队：多位专家分工完成任务。点击 更多 → 项目专家团队，可以新增团队，或点卡片上的“修改”编辑成员职责和 Skill。保存后仍可复用。点击“使用团队（Agent）”将团队说明追加到输入框，补充任务后再发送。适合研究报告、系统开发、合同审查和竞品分析。

工作流：让 AI 按预设步骤处理工作，每步可以指定工具、设置审批。点击 更多 → 工作流 查看模板（采购、预算、付款、发票、合同等），也可以在“编辑器”配置自己的步骤。适合需要严格按步骤执行、重复办理或人工审核的场景；带审批的步骤完成后会暂停，确认后继续。

专家团队：多个角度共同完成任务 | 工作流：按预设步骤执行，记录每步结果与审批

免费范围与商业授权门槛以当前版本随附的 LICENSE 和 COMMERCIAL-LICENSE.md 为准。调用第三方大模型 API 可能产生费用，具体由相应服务商收取。

AgentOS 接入（企业智能后台）

AgentOS 把 macs 的助手变成可被其他软件调用的企业智能后台。网站、ERP 或脚本提交任务后立即拿到任务编号，再查询进度、结果和交付物。

AgentOS 模式是什么？

你在页面里让 Agent 做事；业务系统通过 AgentOS 接口让同一套 Agent 做事。长任务交给后台排队执行，不需要网页一直等着。它提供任务保存、用户隔离、进度查询、审批和恢复。

简单问答

你在对话框提问，模型直接回答。

Agent 模式

你在对话框下达任务，助手使用工具执行。

AgentOS

你的业务后端通过 API 提交任务，macs 执行并保存结果。

本机任务 API 默认随 macs 启动，共用 Web 端口。配置独立端口后，业务系统使用那个端口。“启动时不打开网页”只控制浏览器，不是 AgentOS 的开关。

部署时默认使用 all：同一个程序接收并执行任务。gateway 只接收任务，worker 负责执行；这两种用于分开扩容，单机先用 all。

企业自部署：把 macs 部署到自己的服务器，由自己的业务系统调用，模型也可以使用企业自行配置的服务。任务进度和结果回到原业务系统。

先确定部署位置

最容易跑通的方式是把 macs 和业务后端放在同一台电脑或服务器上。后台的 127.0.0.1 指后台所在机器；云端后台无法通过这个地址调用你家里的电脑。分开部署时需要后台能够访问的 HTTPS 地址。

先分清两个入口

示例中 8080/web/ 是 Web 管理界面；8081 是供业务后端调用的 AgentOS 接口。它们可以使用不同端口。请以自己的配置和启动日志为准。

01 部署：准备程序、模型和岗位
  1. 准备程序。使用与你的操作系统及 CPU 架构匹配的 macs 发布包，解压到固定目录。Windows 程序名为 openkitty.exe，Linux/macOS 为 openkitty。下方命令都在这个目录执行。
  2. 准备配置。首次部署新建 UTF-8 的 openkitty-config.yaml；也可复制包内的配置模板再编辑。已有配置逐项合并下面字段，避免重复写两个 gateway、agents 或 model_cfg。
  3. 连接模型。填写模型服务商的 API 地址、模型名称和 API Key。已有助手可保留原模型配置；下方示例使用兼容 OpenAI 格式的接口，其他类型按原配置填写。
  4. 发布岗位。agents 定义助手，service_roles 把助手发布为可调用岗位；service_clients 给业务后端分配凭证和权限。岗位的 agent_name 必须与助手名称一致。
最小配置：一个模型、一个助手、一个调用方

先替换模型地址、模型名称和两个不同的随机长凭证。模型 API Key 通过启动环境中的 MACS_MODEL_API_KEY 读取。服务凭证直接填写在受保护的配置文件中，不使用模型密钥代替。

headless: true
default_agent: ServiceAssistant
default_model: service-model
model_cfg:
  service-model:
    type: openai
    base_url: "https://your-model-provider.example/v1"
    model_name: REPLACE_WITH_MODEL_NAME
    api_key_env: MACS_MODEL_API_KEY
    max_tokens: 4096
    temperature: 0.2
agents:
  - name: ServiceAssistant
    type: custom
    model: service-model
    system_message: "按用户要求整理工作摘要，清楚说明结果。"
gateway:
  enabled: true
  enable_webui: true
  listen_addr: "127.0.0.1:8080"
  agent_os_listen_addr: "127.0.0.1:8081"
  agent_os_mode: all
  max_tasks: 2
  max_queued_tasks: 100
  task_timeout: 300
service_roles:
  - id: document-assistant
    agent_name: ServiceAssistant
    description: 整理文档并返回结果
    enabled: true
    allowed_tenants: [team-a]
    allowed_callers: [business-app]
tenants:
  - id: team-a
    name: 示例团队
    token: REPLACE_WITH_LONG_RANDOM_TENANT_TOKEN
service_clients:
  - id: business-app
    tenant_id: team-a
    token: REPLACE_WITH_LONG_RANDOM_SERVICE_TOKEN
    enabled: true
    allowed_roles: [document-assistant]
    scopes: ["tasks:submit", "tasks:read:own", "tasks:cancel:own"]

三个凭证各有用途：模型 API Key 用于调用模型；租户凭证用于管理该租户；业务服务凭证用于调用岗位。业务后端只使用 service_clients[].token，保留在后端。

业务服务凭证至少 24 个字符，建议随机生成 32 字节。下面 Windows 命令每运行一次生成一个新凭证；运行两次，分别填入两个 token。

$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
[Convert]::ToBase64String($bytes)
$rng.Dispose()

Linux/macOS 可运行两次 openssl rand -hex 32。默认单机使用 SQLite，无需先安装 MySQL；指定 --path ./workspace 后，默认数据库位于 workspace/.openkitty/openkitty.db。持久保存整个工作目录及配置；已有 MySQL 配置时继续使用 MySQL。

已有源码，如何构建服务程序？

发布包无需安装 Go。源码部署需要 Go 1.26；在仓库根目录运行凭据检查，再构建产品入口：

go run ./cmd/releaseguard
go build -buildvcs=false -trimpath -o openkitty.exe ./cmd/openkitty

Linux/macOS 将输出名改成 -o openkitty。Web 页面已嵌入程序，修改 web/ 后需重新构建；正式发布使用项目 scripts/build/ 中的流程。

准备完成：程序、配置文件和可用的模型凭证齐全；助手名称与岗位绑定一致。

  1. 下载脚本。下载 Python 调试脚本，文件名为 agentos_check.py。
  2. 打开终端。在下载文件所在的文件夹打开终端，先运行 python --version 确认 Python 可用，再执行下面的命令。Windows 也可用 py，Linux/macOS 常用 python3。
  3. 按提示填写。输入 AgentOS 地址和业务服务凭证。凭证输入时不会显示字符，粘贴后按回车即可。
python agentos_check.py
这两个值从哪里找？

服务地址：看配置中的 gateway.agent_os_listen_addr。本指南示例为 127.0.0.1:8081，输入时写完整的 http://127.0.0.1:8081。如果脚本在另一台电脑运行，改为 macs 服务器地址。

业务服务凭证：看 openkitty-config.yaml 的 service_clients，找到 id: business-app 那一项，复制它的 token 值。上面的 REPLACE_WITH_… 是待替换的示例占位符；实际运行需要你生成并填入的凭证。它与模型 API Key、网站登录密码各有用途。

遇到的问题先检查这里
无法连接 / 端口被占用看启动终端是否报错；核对监听地址、端口、防火墙和代理地址。--port 只修改主 Web 端口，AgentOS 端口由 agent_os_listen_addr 指定。
401：未通过认证使用业务服务凭证，检查 Authorization: Bearer …、客户端是否启用，以及代理是否保留该请求头。
403 / 岗位列表为空检查 allowed_roles、allowed_tenants、allowed_callers、岗位是否启用及客户端权限。
404：找不到接口或任务配置独立监听器后，要访问 AgentOS 端口；核对任务 ID，并用提交任务时的凭证和用户身份查询。
400 / 409：请求被拒绝读取响应的 code、message；检查岗位、输入参数、岗位版本，及是否把同一个幂等键用于不同内容。
一直 pending / waiting_approvalpending 检查本机是否为 agent_os_mode: all、是否有可用执行进程及队列容量；waiting_approval 交给具备审批权限的人员处理。
503 / 任务 failed 或 degraded/readyz 返回 503 时先检查数据库和停机状态；任务失败时读任务的 error、result 及服务日志，核对模型地址、密钥、额度、工具权限和超时。

给请求加 X-Request-ID 可关联日志；出错时保留响应中的 request_id 和任务 ID。排查队列可看 /metrics；先查看前台日志或 journalctl，不要把密钥复制到反馈信息中。

04 调用：提交任务，等待结果
POST 提交→202 + task_id + links→GET 查询状态→读取结果与交付物

202 表示任务已接收，任务可能仍在排队。新建任务会调用所配置的模型，按模型服务商或平台的规则计费。先用一条短摘要验证完整流程。

Python 用户：用上一步下载的脚本执行 python agentos_check.py --submit，即可完成提交、等待和读取结果。业务项目接入可使用仓库的 sdk/python/ 客户端；它提供岗位发现、任务提交、查询和 SSE。

PowerShell 完整示例：提交 → 等待 → 获取结果

接着上一步的 $agentBase、$headers 执行；也可在新终端重新运行前面的三行变量配置。超时只停止本地等待，服务端任务仍需继续查询或明确取消。

$requestHeaders = $headers.Clone()
$requestHeaders["Idempotency-Key"] = "summary-" + [guid]::NewGuid().ToString("N")
$requestHeaders["X-Request-ID"] = "check-" + [guid]::NewGuid().ToString("N")
$body = @{
  role_id = "document-assistant"
  message = "将以下内容整理为工作摘要：今天完成了需求讨论与接口设计。"
} | ConvertTo-Json
$task = Invoke-RestMethod -Method Post -Uri "$agentBase/api/v1/agent/tasks" `
  -Headers $requestHeaders -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body)) -TimeoutSec 30
$task.task_id
$taskUrl = $agentBase.TrimEnd('/') + $task.links.self
$deadline = [DateTime]::UtcNow.AddSeconds(300)
do {
  $snapshot = Invoke-RestMethod $taskUrl -Headers $headers -TimeoutSec 30
  $snapshot.status
  if ($snapshot.status -eq "waiting_approval") {
    Write-Host "任务需要审批，请交给有权限的人员处理。"
    break
  }
  if ($snapshot.status -in @("completed", "degraded", "failed", "stopped")) { break }
  if ([DateTime]::UtcNow -ge $deadline) {
    throw "等待超时，任务仍可能运行。请继续查询 $taskUrl"
  }
  Start-Sleep -Seconds 2
} while ($true)
$snapshot | Select-Object task_id, status, result, error, artifacts | ConvertTo-Json -Depth 20

网络中断后重试提交时，保留原来的 $requestHeaders 和 $body，仅重发 POST；不要重新生成幂等键。新工作才用新键。

接口用途
GET /api/v1/agent/roles发现岗位和输入要求
POST /api/v1/agent/tasks提交；新任务 202，幂等重放 200
GET /api/v1/agent/tasks/{task_id}查询持久状态、结果与交付物
GET /api/v1/agent/tasks/{task_id}/eventsSSE 实时进度
POST /api/v1/agent/tasks/{task_id}/cancel取消已有任务
GET /api/v1/agent/tasks/{task_id}/approvals查询待审批动作，需要审批权限
怎样判断完成？

pending 排队、running 执行、waiting_approval 等待审批；completed 完成、degraded 结果有降级、failed 失败、stopped 已停止。后四种是终态；用最终任务快照判断结果，不能把任何终态都当作成功。

完成后读取 result；有 artifacts 时，用响应给出的下载地址取回交付物。下载请求继续携带业务凭证，多用户接入还需同一个用户身份请求头。

进阶：实时进度、Skill、多用户与审批
  • 实时进度：用返回的 links.events 订阅 SSE。断线后查 links.self；收到 replay_reset 也回查快照。Last-Event-ID 只覆盖当前实例近期事件，最终状态以持久快照为准。
  • 指定 Skill：任务可带 skill_run: {"skill_name": "已安装的技能名", "parameters": {}}。参数按该 Skill 要求填写；同一请求不能同时使用 skill_run 和 collaboration。
  • 多用户：业务凭证增加 users:act_as 和 require_user_id: true。提交、查询、SSE、取消、审批及文件下载都携带稳定的 X-OpenKitty-User-ID；提交体若有 user_id，必须与请求头一致。凭证留在业务后端。
  • 审批：另配具备 approvals:read、approvals:decide 的操作员凭证。取得 approval_id 后，发送 POST /api/v1/agent/tasks/{task_id}/approvals/{approval_id}/approve 批准，或将末尾换为 /deny 拒绝。普通任务凭证没有这些审批权限。

接入完成：健康检查通过、岗位可见，并成功取得一次任务的最终结果。正式接入时增加重试、超时处理和业务用户身份映射。
